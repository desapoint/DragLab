# Block installation preparation (2026-10-12)

Third checkpoint of the authorized inventory/engine/block batch. New and used block Purchase → Install, owned Plan install and selected-car inventory Move open one shared preparation dialog. Buying to storage remains a normal purchase. Replacement preserves the current engine identity; engine swaps remain a separate Engines action.

Reuse retains fitting installed parts with their real wear/faults, then proposes actual compatible unreserved loose sets for missing slots. It never buys missing companions automatically. Manual exposes each required or present engine/electronics category and its fitted, cart, loose or new source. Missing choices are visible drafts; an incomplete/nonrunning proposal cannot be staged. OEM proposes actual required factory sets with the correct modeled counts and explicit cumulative cost; optional fitted hardware stays unless changed explicitly. Existing supporting cart rows are disclosed and preserved rather than overwritten.

The dialog reuses current/planned/no-wear dyno, summary delta bars, information dialogs and operating warnings. Add plan stages the reviewed core and companions; normal cart confirmation publishes them atomically. Cancel/X, stale revisions/cart signatures/prices and failed persistence retain live assets/resources. No preview saves, free components, healing or fluid refills. Removed parts and surplus cores stay owned. Whole sets remain the default, with the existing matching-specification individual replacement workflow available elsewhere in purchase/cart/stored-engine preparation.

Prepared core editing retains companion choices and quantity; Store removes unmodified associated support rows. Removing the core removes only its automatically associated rows; explicitly edited companion rows become independent. Cart completeness checks cover block moves into other cars too; select that car to prepare its replacement. Inventory Move uses this same planner for the selected-car block. Same-specification maintenance remains the established part workflow. The retained legacy F8 interface/direct part APIs have not been redesigned; this checkpoint delivers native preparation and authoritative cart validation, not a blanket replacement of every old immediate-install API.
