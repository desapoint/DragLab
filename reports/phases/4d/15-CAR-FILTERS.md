# 4D.8 — Owned-car search, filters and sorting (2026-10-10)

The user explicitly requested all listed browsing controls together. This checkpoint adds them to the existing two-card-per-row owned grid; it does not start dealership, paint, inspection-drawer or later interface migration.

## Changes

- Add a concise toolbar with live text search, Filters, sort field/direction, view reset and matching/owned count. Search matches name, model, instance, body/configuration terms, ignoring case/accents. Filters intersect; ascending/descending sorting keeps acquisition order for ties. The default owned order retains the existing collection layout. Query state stays in the UI session across details, F8, Settings and resizing, without saving.
- Provide rank F–S, drivetrain FWD/RWD/AWD/4×4, body type, transmission, induction and readiness choices. Readiness uses existing complete/reserved/fuel/component-condition status. Numeric inclusive min/max ranges cover PP, HP, torque, weight and lowest wearing-part pack condition; blank is unbounded. Torque inputs use selected Nm/lb-ft units and compare canonical Nm. Invalid, non-finite, negative and inverted ranges reject; PP and condition enforce their meaningful 0–999 / 0–100 bounds.
- Sort by owned order, name, rank, PP, HP, torque, weight, condition, drivetrain, type or transmission. Unknown/uncompleted numeric ratings remain unavailable, last in either direction, and cannot pass numeric bounds. Rank/PP use the existing copied automatic quarter-mile estimate and Benchmark.Rating authority; add PP beside Class on cards/details. No rating formula or driving behavior changes. Pending rank filters explain calculation rather than claiming a permanently empty collection.
- Author body-type metadata for all eight current models (two hatchbacks, four coupes, one sedan, one pickup). Future SUV/wagon/van/roadster categories are available without fabricating cars. Unauthored metadata displays Unspecified; classification is independent of placeholder sprite shape. VehicleSpec copies retain this additive metadata without changing physics or owned identities.
- AWD matches the modeled AWD family. The 4×4 filter is an explicit subset for effective locked-center AWD, including applied coupling configuration; drivetrain sort distinguishes it. It does not introduce a new simulation drive mode or claim all pickups are 4×4. ASCII 4x4/4WD search aliases are supported.
- Filter/sort dialogs reuse native joined choices, numeric inputs, red Apply/grey Cancel, corner-highlight panels and scrolling. Choices are drafts until Apply; filter-dialog Reset is also a draft. Toolbar reset clears the browsing view immediately. Existing hover/pressed/selected-value styling and no Tab/focus decorations remain. Move modal-decoration cleanup before content population so new choice surfaces are retained/animated and older ones are removed.
- Cache applied summaries and completed ratings; query gestures only hide/reorder cards. No new captures, probes, selection, transactions or saves from browsing. Definitive profile/unit refreshes retain the existing rebuild/cancellation path.
