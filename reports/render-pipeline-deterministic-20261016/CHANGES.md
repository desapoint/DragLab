## Capture protocol

`--draglab-deterministic-capture` requires an explicit game or bench verification-folder argument and a Windows development player. Ordinary games and the Editor retain real UTC time and random unique IDs. The new shared time/identity seam does not change physics or saved identities; it controls newly generated fixture identities, market seeds and time-dependent test data. Both pipelines use the same initial database snapshots, with hashes recorded alongside this run. The orchestrator rejects a player that fails to emit capture-protocol evidence.

Each suite uses the same isolated fixture path in both phases. The preceding fixture/output is archived under checked workspace paths before its replacement, preserving original evidence. Generated configuration/export paths are stable. Capture waits for pending ratings, inspections and part comparisons, then freezes advancing simulation during the screenshot. Hover shine and switch transitions have fixed sample phases; ordinary pointer states are cleared except deliberate hover examples. Repeated screenshot names get an explicit occurrence suffix, preserving both the initial dealership and its post-reset repeat instead of silently overwriting one.

Live race pictures use a fresh copied stock fixture stepped by the authoritative simulation at 120 Hz until the named speed, time, finish approach or result. The original functional-test race and result are restored before input resumes. Manual sound-bench pictures sample 360 fixed ticks using the current configuration and controls. Recorded physical-bench scenarios/replays retain their actual fixed-tick traces. Tire-smoke integration uses a fixed step only in capture mode. These are presentation fixtures, not claims that an arbitrary live race has the same keyboard timing in both runs.

The original migration gallery, images and contract remain under `reports/render-pipeline-20261016`. This run is separate; no thresholds, image masks, registration or color normalization are used to obtain a pass.
