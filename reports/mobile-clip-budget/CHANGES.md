# UI clipping allocation correction — 2026-10-18

The reported Android development-console message was reproduced exactly in an isolated Windows player: unrestricted Engine shopping materialized **2,226 cards** and exhausted the UI Toolkit panel's **8,191 usable clip entries**. The message can remain visible after changing to Race, although the allocation occurred while rendering the shop catalogue. Baseline: `clip-budget-baseline-20261018-b` (expected failure, one allocator error).

The Build grid now materializes only viewport rows plus overscan, retaining full two-column scroll extent with non-clipping spacers. Offscreen controls/decorations are released rather than retained as thousands of hidden/clipped text elements; leaving Build releases its attached cards. Matching/sorting/counts use the full data list. Product IDs, previews, individual components, prices, quantities, reservations and transactions are unchanged. Existing shared card/control styles, touch panning, scrollbars and desktop F8 are retained. Verification helpers scroll the intended product into the materialized window before targeting its real button.

Row-window changes happen during the normal menu update, outside GeometryChanged callbacks. Tests caught and corrected layout recursion and cumulative mobile pixel-rounding drift in intermediate versions. Spacers use the existing theme's logical 230-pixel card plus 16-pixel bottom margin (246 per row), rather than deriving a global stride from a pixel-rounded card at one scroll position. These intermediate players were not accepted as completed checkpoints.

The focused regression measures actual owned clipping IDs in the running Unity renderer, visits all five unrestricted categories in desktop and simulated-touch modes, checks bounded attachment, sorted identities, midpoint/end/start scrolling, last-product reachability, release on navigation and unchanged profile/save bytes. A separate pure layout gate covers 210 count/viewport/offset combinations, including odd counts and large offsets. Final gates: 210 pure layout cases, 134 actual-renderer clipping checks, 1,053 Parts interface checks and 171 touch/mobile interface checks passed. The three player gates reported zero runtime errors. Unrestricted categories attach only 8 desktop / 6 touch cards, using 449–509 owned clipping entries; see clip-budget-matrix.csv. Windows development player built successfully. Android packaging is recorded in build-manifest.txt and packaging-verification.txt; physical-device acceptance remains separate.

Unity's implementation reference for the allocator limit and clip ownership: [Unity 6000.6 ShaderInfoAllocator](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.6/Modules/UIElements/Core/Renderer/UIRVEShaderInfoAllocator.cs). Runtime reflection is limited to development verification; normal game rendering uses no private Unity API.

The approved seeded supply diagrams and wear/coverage rules are already recorded separately in docs/PARTS_SUPPLY_FLOW.md, commit 0d61c77. Supply implementation follows this clipping checkpoint and is not included in this UI fix.
