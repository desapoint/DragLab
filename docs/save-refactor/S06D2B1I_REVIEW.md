## Contract review

The scope is the physical `PartInstance` move family across Storage, Car and detached Engine. Individual loose units and whole engine assemblies remain separate families. The contract correctly requires a single ordered transition core for the live `SharedInventory.Move` route and the synchronous private projection, while preserving the legacy unit/engine branches and their classification precedence. Run/storage guards precede asset-family lookup; classification remains loose unit, engine, then part using current list-first semantics; part destination validation follows the part lookup and precedes source removal.

The private adapter is lazy and scoped to one owner-thread evaluation. It does not prevalidate a donor or target, build a profile-shaped mirror, clone a profile/catalogue, yield, or retain borrowed state. Copy-on-read and the overlay must preserve ordered first-match behavior and represent distinct source objects independently even when identifiers collide. Shared transition logic, not either adapter, owns guards, detach/remove, displacement, install and target rank projection. Successful results contain only owned affected records/build snapshots; failures contain exact error type/message and no candidate graph. Legacy partial mutation on failure stays observable in the live route; only private staged mutations are discarded.

The contract's no-heal boundary is placed at the existing late engine-install `Ensure` stage. Its predicate matches the current implementation: only when `EngineElements.Count(spec, definition) > 0` and `condition.elements` is null/empty does legacy Ensure generate members. Count-zero empty state remains valid; any nonempty correctly typed array remains accepted as-is, even if its length differs from the expected count; a nonempty wrong-type array retains the existing exact error. The new projection refuses only the generation case at that same stage, with a named typed error, and the live route keeps legacy generation. A prior destination/slot guard must still win over that new refusal.

One additional implementation constraint follows from the H prerequisite: `ConcreteInstalledBuildInput.Capture` currently accepts a `PlayerProfile` and `OwnedCar`. Resolver/inspection parity for a private overlay must consume the overlay's exact owned facts through a narrow typed factory/overload; it must not build a partial `PlayerProfile` or resolve the source car instead of the proposed build. Preserve the H resolver as the authority and keep the catalogue borrowed synchronously.

The finite contract is appropriate for this prerequisite: real Storage, occupied-Car and detached-Engine destinations; installed source moves; exact displaced identities and tune effects; precedence/partial-failure probes; valid, null/empty, zero-required, short/long nonempty, and wrong-type member controls. It does not claim the full source/destination Cartesian matrix, every malformed cart case, or future ticket freshness. Existing JSON/source-invariance failures remain strict and open; they are not a reason to block this dormant shared transition prerequisite, but continue to block whole-preview conversion and Step 1/S06 completion.
