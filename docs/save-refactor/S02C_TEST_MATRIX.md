# S02c ownership validation lookup checks

S02c compares the public `MechanicsOwnership.Validate` with a test-only copy of the ordered-scan implementation captured from baseline `7e6ea10`. The reference copy preserves the original validation body, rejection order, messages and `List.Find` paths; only its method visibility/name and the `SaveVersion` qualifier differ. Both files containing the reference and harness are editor-only. No validator test serializes or JSON-round-trips runtime data, writes a profile, or clones a whole profile.

| Area | Implemented coverage |
| --- | --- |
| Exact parity | Run the frozen scan reference and public validator on the same typed fixture. Compare exact error string or exact exception type and message, and require an expected acceptance/rejection/exception class so equal but incorrect results cannot pass. Verify top-level collection and record-reference order, plus a deterministic reflection fingerprint of all persisted instance fields and nested references, are unchanged across both calls; include `storageCommit` explicitly. The fingerprint is Editor-only test diagnostics, not a serializer or clone. |
| Valid authored state | Build profiles through `Resources.LoadAll` plus `PlayerProfile.New` / `MechanicsOwnership.Ensure`, then compare valid cases with 1, 5 and 20 cars and 0, 24 and 96 inventory spares. Exercise attached and legitimately detached engines. Use installed tire/wheel member wear and piston faults only when `EngineElements.Faults` / `FaultAllowed` allow them. |
| Adversarial typed mutations | Independently exercise duplicate part IDs, unbound vehicle-located orphan parts, cross-car owner mismatch, duplicate member IDs, wrong slot category, attached-engine parent mismatch, selected-car reference mismatch and a disallowed tire-member fault. Each case starts with a fresh authored fixture, changes one typed record or binding, compares both outcomes, and checks source values/references afterward. |
| Malformed scan fallback | Add a null car, engine, part, or binding row to separate valid fixtures and compare exact legacy exception timing/type/message. These cases exercise the lookup's scan fallback for malformed source families and bindings. They do not imply that malformed profiles are normalized or accepted. |
| Null identity semantics | Directly exercise first-match lookup behavior for repeated null IDs, distinguish null from empty strings, verify ordinal case sensitivity, and check first matching binding owner for a null part ID. A validator fixture with a null part identity and binding confirms legacy lookup resolution before the existing later rejection. |
| Performance | Time the entire original scan validator and the public indexed validator on equal valid fixtures for the 3×3 car/spare matrix. Use three paired alternating-order warm-up pairs and twenty measured pairs, alternating legacy→indexed and indexed→legacy. Preserve every per-call timing and generation 0/1/2 collection-count delta in CSV; summarize median and sample maximum in the text report. Ordinary garbage collection remains part of the timed workload. No p95/p99 or allocation claim. CSV includes actual car, spare, part, and installed-binding counts. This is a Unity Editor validation workload, not a device, frame-latency, or save-transaction benchmark. |

Fixture IDs produced during authored normalization use runtime entropy, so the inputs are pinned by authored content and logical counts/invariants, not byte-identical whole-profile hashes. Spare records are copies of one existing typed component only, with stable unique test IDs and inventory ownership; no full profile is copied. The validator is read-only; the harness compares both source list object identities/order and typed value signatures before and after. All measurement regions contain complete validator calls. No component index is built in the test code, and no additional production mutation is authorized by this matrix.

The coordinator runs `DragLab.Runtime.OwnershipValidationLookupChecks.RunStandalone` in Editor batch mode, outside Play Mode, and records raw output under `reports/save-refactor/S02C/`. The per-call CSV exists to expose ordering and GC phase effects across paired samples; no GC is forced or selectively excluded. This matrix describes the revised benchmark method and does not claim execution or completion. The independent reviewer and coordinator record actual counts, measured costs and any remaining behavior differences after the rerun.

Final-source supplemental probes cover double Dispose, all five post-disposal query methods, first non-null duplicate relation ownership, malformed bindings after an early match and before an absent match, plus even/odd arithmetic median summaries. They use direct typed helper inputs; no player state is copied or persisted. See the results for actual full-run versus supplemental-source execution.
