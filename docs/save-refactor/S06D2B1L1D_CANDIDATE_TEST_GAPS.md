# L1D candidate test gaps after Reference B

Status: **independent test-planning note only**. This note authorizes no source edits, checker wiring, Unity run, build, Git operation, or production/caller approval. It supplements the full-cart test design; it does not replace or narrow it.

## Evidence boundary

[Reference B results](../../reports/save-refactor/S06D2B1L1D_REFERENCE_RESULTS.md) report 730 passing assertions, no failed assertions, no OPEN prerequisites, and no runner exception against the independent frozen legacy reference. That result establishes old-live/frozen-reference liveness only. It is not typed-candidate parity, purity, player, device, performance, or acceptance evidence. The corrected checker still needs its independent review and the production call closure/edit allowlist remains open.

The old preview characterization explicitly reports `LEGACY_PURITY|FAIL` for all 29 observations: 16,037 changed field paths and 2,840 changed reference paths across repeated scenarios. Those are required candidate divergences. A candidate must not reproduce source repairs or mutations just because the frozen oracle did. This is especially important for Ensure/JSON preview behavior and malformed existing conditions.

The [semantic closure audit](../../reports/save-refactor/S06D2B1L1D_SEMANTIC_CLOSURE_AUDIT.md) is source-analysis evidence, not runtime closure: it retains 1,559 OPEN records. The [physical dispatch proposal](S06D2B1L1D_PHYSICAL_DISPATCH_PROPOSAL.md) identifies the conditional catalogue/JSON route and the unresolved base/override `Failed` property dispatch. Neither document turns an OPEN edge into a passed runtime check.

## Candidate-specific tests to make explicit

The existing [full-cart test design](S06D2B1L1D_CART_QUERY_TEST_DESIGN.md) already specifies the broad mode, boundary, row, clock, output, and freshness matrix. The following are the remaining executable proof obligations that a reference-only pass cannot satisfy. If equivalent candidate vectors are already added, link their case IDs and retain the stated assertions rather than duplicating them.

The first, second, fourth and fifth rows are the clearest additions beyond the legacy liveness result: they prove candidate purity, purpose isolation, scoped-read purity, and that physical work cannot enter the conditional JSON/synthetic-component path. The remaining rows make the approved DTO/input/lifetime contract executable rather than inferred from output shape.

## Keep already-specified coverage intact

Do not treat this note as permission to omit items already in the main test design: invalid API precedence and no-read assertions; per-mode null/iterator failures; Total/Fee reservation differences; lazy default-time behavior; local/express/mixed stock; q0/q1/q2/q99 and 100/101-row boundaries with real eligible authored offers; sale funding and pricing; Move-only Total validation; block readiness; requested current/proposed captures; all-mode Combined continuation; exact typed output fields; and native/performance/caller gates. These remain mandatory even if Reference B passes.

For every test expected to succeed, assert the intended branch/output was reached, not merely that candidate and reference produced the same earlier error. For failures, pin the independently established first error, including stage, type, message, parameter and row index. Any unconstructible required case is a blocker/OPEN prerequisite, never a pass or skip.

## Gate interpretation

Reference B may be used as a frozen expected-value oracle only for the old behavior it actually covers. Candidate purity and the intentional no-heal divergences above need their own source-state expectations. The 1,559 semantic OPEN records and physical dispatch OPENs remain closure obligations; do not count their absence from test failures as closure. High review, the final finite implementation allowlist, candidate differential run, caller integration, Windows/native/performance and full S06 acceptance are later gates.
