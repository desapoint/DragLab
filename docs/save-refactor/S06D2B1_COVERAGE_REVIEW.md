## Additional entropy-stream gate (source-level hypothesis, not an observed defect)

The current checker captures only `UnityEngine.Random.state`. `RuntimeEntropy.cs` defines an independent private per-scope `sequences` dictionary: with `Capture` active in a Windows Development standalone build under its deterministic-capture command-line flags, `NewGuid(scope)` increments that sequence; outside that build/editor condition it returns `Guid.NewGuid()`. `MechanicsOwnership.NewId(kind)` routes through `RuntimeEntropy.NewGuid(kind)`, and the domain source shows new physical parts/elements can use that identity path. The frozen preview applies purchase rows to its isolated profile, so this is a source-level path by which legacy preview work could advance the actual capture identity stream even while Unity random state remains unchanged. This has **not** been observed in a native trace and must not be described as a proven defect.

Add a native-capture matrix check around the actual Move/preview callback envelope and a minimal purchase preview: record read-only per-scope identity sequence counts immediately before and after; assert that read-only preview and cancellation consume no authoritative identity values. Provide a read-only per-scope counter probe if necessary; a read-only reflection read under the existing synchronization is also acceptable. Do not reset, seed, override, or otherwise mutate the private sequence for the test. Record exact scope deltas alongside Unity RNG and source graph checks. The eventual typed preview request-local virtual IDs must not call `RuntimeEntropy.NewGuid`, allocate authoritative IDs, or affect subsequent gameplay ID sequence. Editor runs have `RuntimeEntropy.Capture == false`, so they cannot close this native-only gate. Keep native callback status OPEN pending actual capture evidence.

The clone has a reference-identity map for cycles/aliases, handles arrays including rank/lower bounds, exact `List<T>`, immutable scalar values, serializable DTO fields and persistent authored Unity assets, and rejects unsupported graph shapes without JSON fallback. It does not call `ProfileStore`, save, gameplay preview, or runtime fallback.

`CatalogSnapshot` covers `catalog.parts`, `AuthoringRevision`, and each original private authored spec value read by reflection, rather than the copying `Spec()` accessor. Because the authored catalog reference is intentionally shared, each active comparator snapshots it after the production call. If production changed catalog or the original fixture, it asserts and explicitly skips the frozen oracle. Otherwise it confirms the legacy copy still matches its pre-call snapshot and runs the oracle independently. The same separate-input behavior applies to Fee, Preview and Apply. `JsonUtility` remains only in the separately labelled mutation-boundary diagnostic probes; it is not used to isolate comparator inputs.
