# S02a owned-part identity index checks

This checkpoint validates one runtime identity/ownership index family against an independent ordered-list scan. The synthetic scaling fixture and oracle use deterministic `PartInstance` IDs and managed object references; the separate authored checkpoint profile uses normal in-memory `MechanicsOwnership.Ensure` initialization and generated IDs, so its fixture is invariant-based rather than byte-for-byte reproducible. No test JSON-round-trips, clones a whole profile, touches `ProfileStore`, or accesses a player save. The checkpoint regression intentionally mutates only its disposable in-memory authored profile. Checks are Editor batch only, outside Play Mode. The coordinator owns Unity execution and raw output under `reports/save-refactor/S02/`.

| Area | Implemented check |
| --- | --- |
| Differential lookup | Compare strict full-map and sparse requested-ID results with `List.Find` using identical ordinal IDs; cover present, absent, unrequested-present, and case-different IDs. Strict build rejects duplicate/null/blank source rows. Sparse build rejects null/blank/duplicate requested IDs, oversized request sets, malformed rows it scans, and duplicate scanned source IDs that were requested. |
| Candidate-local structure | The index is one-shot and bound to the exact list object. Separate candidate fixtures compare to fresh scans after same-count replacement plus add/remove. After disposing the prior index, the original source list is changed by same-count identity replacement and reorder; each gets a fresh index and is compared with the scan. No incremental update API is implied. |
| Operation lifecycle | Each operation scope builds and disposes its own index. Two distinct synthetic part lists of equal size (standing in for profiles with the same revision) never resolve each other's IDs. Profile revision or count alone is not a source identity; the index is never cached globally or retained across callbacks/publication. |
| Mutable condition | Change condition/wear/history on a synthetic part without changing identity or list structure. Identity lookup must retain the same `PartInstance` reference and resolve the same IDs; no mutable mechanics payload may be copied into the index. The public checkpoint regression separately covers fluid changes and verifies the index-backed application preserves them. |
| Checkpoint preservation | Exercise public `MechanicsTransactions.ValidateCheckpoint` and `ApplyCheckpoint` with an authored in-memory profile and a `RunPersistence.Capture` checkpoint. Assert validation leaves source records/resources/receipt unchanged; late thermal, late condition, duplicate identity, and missing prior resource failures leave all captured source fields and references unchanged. On success compare stable part IDs and ownership/location, copied member wear/fault/history, fuel and fluid quantities/history, exact run receipt advancement, and unrelated inventory condition references. No profile serialization or durable save occurs. |
| Sparse-request validation limits | `BuildRequested` returns after all requested IDs are found and does not claim to validate unscanned tail rows. A duplicate tail after the final match is deliberately demonstrated as outside its validation. Null/blank rows encountered before the last requested match fail; if a requested ID is missing, scanning reaches the tail and rejects malformed rows encountered there. Source-wide uniqueness/topology must be prevalidated before this fast path is used. |
| Cost characterization | At 100, 1,000, 10,000, and 30,000 parts, compare strict full build, full lookup-only, measured full build-plus-lookup, sparse build, sparse lookup-only, measured sparse build-plus-lookup, and `List.Find` for identical 64-ID first, last, deterministic shuffled, and missing groups. Use five repeats; report median and sample maximum only (not p95/p99). Report strict/sparse entry counts, referenced ID UTF-16 payload bytes, and a 24-byte-per-entry structural lower-bound estimate before alignment/capacity/object headers; this is not a heap measurement. Caller-thread allocation counts are omitted because the available counter was unreliable in prior Editor probes. |

The synthetic scaling fixture has fixed ordinal IDs and uses 64-query groups; it is not a complete gameplay profile or save transaction. Strict `Build` validates the full part list and costs O(N) even for early IDs; `BuildRequested` holds only requested matches and may stop after the last requested match, but its unscanned tail must already satisfy caller-owned source-validity invariants. Missing IDs require a complete scan. The comparison includes end-to-end build-plus-query cost so early-list regressions remain visible; no speedup is assumed until the coordinator reviews the measured output. A separate authored in-memory profile exercises the real public checkpoint validation/application flow without persistence or serialization. These checks must not be described as proof that other production commands are migrated. Runtime changes remain limited to the S02a index family; no whole-profile clone or JSON manipulation is acceptable in the index or check harness.
