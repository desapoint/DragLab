# S06c typed refill pilot verification

This harness exercises the active manual oil/coolant pilot against disposable SQLite state and an advancing player UI. All database/profile paths are temporary beneath the runner's output directory. The fixture starts from `PlayerProfile.New`, assigns an authored vehicle, calls `MechanicsOwnership.Ensure`, and persists through the selected `ProfileStore` owner before testing. It does not use the New Game cars-zero template or typed writer results as the expected-value oracle.

| Area | Independent evidence / expected result |
| --- | --- |
| Legacy parity | Calculate price and capacity-clamped additions with `PaidEconomy.Preview` and detached `ServiceOperations.TopUp`; compare cash, exact target oil/coolant bits, revision/clock, and receipt fields after the real typed SQLite commit. Snapshot all 14 fluid fields and verify only the two requested quantities change. |
| Quote and owner fences | Exercise exact policy quote expiry, changed quantities/cash/price/target, stale profile revision/storage token, slot/path/epoch and selected reference. Stale terms refuse without repricing or mutation. |
| Delayed worker | Hold the injected SQLite writer at a deterministic boundary. Repeated owner polls return promptly while the live profile, cash and fluids remain unchanged; status reports pending and confirm is disabled. |
| Single intent | Double dispatch/confirmation and competing admissions produce one operation ID, one writer dispatch, one durable receipt and one charge. Closing the originating dialog does not cancel retained work. |
| Unknown and retry | Simulate lost acknowledgement after durable commit, retain unknown state, retry/reconcile using the same intent and prove exact one-effect state. Definite uncommitted rejection is reported without patching the live profile. |
| Publication safety | Inject publication failure and mutate owner/read-set or select a newer owner after commit. Keep the durable result recoverable; do not overwrite newer cash, fluids, navigation, or settings. Historical replay auto-publication is allowed only when its observed storage token equals its committed token. |
| Recovery | Exercise explicit validated recovery for a retained committed result, preserving separate preferences/drafts; failure leaves the operation recoverable and lease/action fences active. |
| Current-token replay | Commit an operation, advance the same database with a second typed command, then reconcile the first intent. Its historical result must remain unpatched when the transaction observes a newer commit. Duplicate admission must preserve the recovery result; explicit validated recovery must return the latest owner with both receipts. |
| Definite rejection / reuse | Inject a pre-COMMIT failure after receipt absence is proven, verify truthful rejection and unchanged live/durable cash/fluid/revision/receipt state, then request a fresh quote after owner proof is restored. Lost acknowledgement and explicit reconciliation are covered separately. |
| Read-set publication fence | Commit in SQLite, then change live cash and a non-target fluid field before owner polling. The pilot must not partially apply any patch; explicit recovery returns the durable after-image. |
| Cache and stale terms | Check the eight-entry quote-cache limit, exact expiry refresh, policy-sensitive key changes, and rejection of a shown quote after a cash read-set change. Re-request the exact same key after direct same-revision cash and physical-fluid changes and require a fresh quote instance with the changed facts; mutate the receipt window and confirm the cached terms are not returned. Newly added garage-job and unsettled-run blockers must still fail through the normal planner path. |
| Other fluids / actions | Verify all 14 fluid bits, component/engine identities, wear, faults and unrelated resources remain unchanged. Legacy top-up entry points branch before JSON. Race entry and audited direct mutation paths are fenced while pending. Automatic race top-up remains the named S10 caller. |
| Bounded work | Check quote cache key/context/expiry behavior and affected-only publication/receipt patch bounds (at most 256 entries). Managed output records desktop fixture timings for a cache-miss quote admission (including planner Capture/Plan), a validated cache hit, held-worker `Poll`, completion `Poll` including publication, and writer-release-to-publication elapsed time. These observations have no performance pass threshold beyond the separate nonblocking held-worker poll check and do not imply whole-player/UI guarantees. |
| Native dialog | On an advancing standalone player, open existing-car refill, verify shared slider and money preview, reject a stale shown quote, hold the SQLite worker, and observe pending status/disabled confirmation over multiple frames. Exercise duplicate confirmation, view close, navigation, preference save, race-entry exclusion, and a fresh dialog after success without rebuilding during slider capture. The separate `TypedF8FluidRefillChecks` coroutine covers visible desktop oil, coolant and combined actions through the same pilot. Parent-run native70/0 and F8 52/0 are recorded in S06C_RESULTS.md; each includes40 common onboarding/starter checks. Unknown/retry/failed-recovery, interruption/resume and the full-frame performance gate remain required S06d work, with general OS forced-termination soak retained for S14. |
| Cleanup | Restore all hooks, static paths, selected slot/owner state, and preferences in `finally`; keep native fixtures on the isolated player profile and restore user resolution/input state. All synchronization waits are bounded and released in `finally`. |

These are required checks, not evidence that they have run. Managed checks and native interface/build evidence are reported separately; a passing automated interface check does not constitute visual user acceptance.
