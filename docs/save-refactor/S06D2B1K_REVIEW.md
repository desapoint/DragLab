## Contract review

The bounded API is correctly limited to ordered raw-domain moves of physical parts, whole engines and loose units to Storage or supported existing destinations. It introduces no cart validation, pricing, purchase/sale, worker, ticket, persistence or UI authority. Immutable request capture preserves order and null entries. Empty input is an identity operation with empty owned outputs and no domain reads; the API has no request cap, and repeated asset requests are not pre-rejected. Null container and null-row failures have explicit indices and do not acquire new validation semantics.

The central contract requirement is one private working set and one shared dispatcher. Each row reuses the existing preamble/classifier and authoritative unit, I part, and J engine operations against that same state. Existing live `SharedInventory.Move` uses the same dispatcher with legacy part-member behavior, while private projection uses `ProjectionRequireExisting`. Thus later rows see prior private writes, and the projection does not invent a second move authority.

The overlay ownership lookup is sufficiently precise: scan cars in source order, consult private bindings only for wrappers already loaded, and otherwise read source bindings without wrapping unrelated cars or copying parts. Preserve first-match and subsequent first-car-by-ID relookup behavior, including original null-installed/list/row exceptions. This supports engine A-to-B followed by a part move from B while avoiding eager copies during lookup. Stored-engine part binding writes must add the actual engine to `ChangedEngines`; attached-car binding edits must not claim an engine-slot write.

Loose-unit state is keyed by source record reference, copies scalar storage fields lazily, and uses polymorphic element copying to retain `TireCondition` and all member fields/IDs. Unit moves write only storage identity; no tire synchronization, defaults, installation, validation or new IDs are introduced. Ordered final outputs are owned, source-reference-deduplicated snapshots of written parts, engines and units plus first-affected-order car snapshots. Track records actually written even if later rows return their values to the starting state. Materialize only final snapshots; keep optional materialization errors separate from sequence success.

Failure returns only error type/message/index and no output/write arrays, including when earlier rows succeeded in the private candidate; disposal leaves the input unchanged. Live/frozen sequencing retains legacy partial effects. The scoped copies and output ownership rules exclude profile/catalogue mirrors, JSON, Ensure, clocks, RNG and borrowed source references escaping evaluation.

The finite fixtures are targeted to the remaining cross-row risk: mixed engine/part/unit order, reversed order, failure after a successful row, 100 repeated unit requests, and separately 100 distinct real owned-part requests. The distinct-asset capacity requirement is not replaced by repeated-row evidence. Actual acquisition is required; fixture absence remains open/failing, not a skip. The bounded family-collision, request/preamble and empty-input controls are appropriate. This is a finite contract, not an exhaustive malformed-state or alias matrix.
