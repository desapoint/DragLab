# S06d2a bounded Parts browser test plan

Scope: audit and verification contract only. Current `NativePartBrowser` construction is synchronous in `RefreshParts`; the result is cached per `PartsPage` and cleared when the context key changes. UI query/sort/filter application, comparison evaluation (already time-sliced at about 3 ms/frame), and virtualized card rendering happen in separate steps. The measured ready-shop sample still fails the whole-frame gate: `nativeParts` 89.475 ms and `frameMs` 124.561 ms; attribution was representative selection 8.736 ms, supply count 19.256 ms, quote/hold 17.647 ms, entry creation 6.369 ms, aliases 1.851 ms, and used offers 0.109 ms. Another native capture attributes about 6.8 ms to current inspection, 55.8 ms to Shop population and 27 ms to first visible-card rendering. The proposed `NativePartBrowserBuild` should incrementally prepare a private complete result on the owner thread, with a measured 2–3 ms soft step budget plus a fixed item cap. Split expensive inner loops at exact candidates/rows; do not move a single whole constructor or oversized finalization step. Any pure math worker may receive only a detached immutable `InspectionBuild` snapshot. It must never receive a live profile/catalog/part/UI reference or a callback that closes over game state. Visible cards remain owner-thread work and need their own bounded publication/render step.

## Typed input and publication fence

Capture only fields that feed the requested page/result; do not clone the whole profile or add JSON fingerprints. The build token must include:

- Owner identity: capture `ProfileStore.CaptureSelectedContext(out slot, out canonicalPath, out epoch)` on the main thread; compare slot/path (using the platform's path-comparison rules) and epoch, plus `PlayerProfile` reference, `storageCommit` and `revision`. This read token is separate from command proof and remains usable when a legacy command proof is dirty.
- Catalog identity: catalog reference, authoring revision, ready-group snapshot/map identity and a strict current `TryReadyShopProductGroups` check at publication. That strict check must reject public-field edits and same-count object replacement.
- Selection/plan identity: selected car reference and instance/vehicle/engine IDs; page and planned/current mode; an ordered typed copy of every cart line field (`definitionId`, quantity, install/prepared flags and owner, action, asset, role, destination, and ordered positions).
- Commerce inputs: market seed/generation and row identities/order, aliases/units/delivery percent/discovery data read by the page; reservation owner/clock/car/generation/supply; inventory asset identities and condition inputs; dealer identities/definitions plus captured typed values used by used/sale pricing; cash/reputation where consumed.
- Display/inspection inputs: `UnitPreferences` version/speed/pressure/torque; reference map/spec; and an explicit typed selected-car read set covering exactly the values consumed by `InspectionBuild.Capture` (tune, fuel, fluids, fitted identities, component conditions and definition/spec values). Profile revision alone is not enough for same-revision direct edits.

Query/search, sort, filters, selected section, scroll offset, selected detail, modal identity and drafts are live presentation state. Query/resize/page changes invalidate the visible-window ticket; if base preparation does not read a control, reapply its *latest* value after completion and preserve selection/scroll. Never publish a partial entry/card list as current. On any input-fence mismatch, discard and restart from a fresh capture; do not clear existing warning/critical text or allow an old card action to act. Assert a worker payload contains no live `PlayerProfile`, `MechanicalCatalog`, `PartDefinition`, `PartInstance`, Unity/UI object or game callback; detached `InspectionBuild` nested spec/definition data must be proven detached. The nonempty-cart `PartCart.PreviewProfile` full-profile JSON clone remains explicit required legacy debt: keep it on the owner thread, cover its parity and native latency, and do not call the path optimized or exclude it from the S06 acceptance gate.

## Deterministic gates

Use a development-only step gate that pauses real preparation between bounded steps; releasing it continues the same real build. It must not manufacture a result. Compare completed output to the synchronous reference on the same fixture with typed assertions: ordered entry/card IDs, definitions and assets, representative/aliases/search, ownership, compatibility/reason/warnings, price/stock/express, comparison changes and query ordering/stat precision. Assert only the current virtual window creates UI elements and that each step has a fixed item cap plus a soft time budget. Record the largest step; no single oversized final step may be hidden by averaging.

| Change while a real build is held | Required outcome |
| --- | --- |
| Same-profile commerce/part commit; same-revision direct market row, hold, part-condition, fuel/fluid or authored-definition edit | Old token is rejected; latest stock, warning, fit and comparison state is rebuilt. Include direct field edits without a revision bump. |
| Selected-car switch; same-ID asset replacement/removal; profile replacement/reset; save-slot/context load or owner-epoch change | No old result or action publishes. Restart for the new owner/car and prove IDs resolve to current objects, including a context change with the same `PlayerProfile` reference. |
| Add/edit/remove/reorder cart lines, including quantity, install, prepared owner and ordered positions | Stale plan is rejected. Empty-cart and nonempty-cart cases both retain exact synchronous output; no claim of a nonempty-cart speedup. |
| Navigate away / F8 change, or change Parts page while pending | Hidden/old page does not publish into the new route. Returning opens a fresh or still-current build. |
| Change search, filters, sort, category, scroll or detail selection | Reapply the latest view state at completion; preserve scroll/detail when the same entry remains. On resize/rebuild, retain the selected item and scroll, with no partial or stale cards. |
| Change unit preferences or open/act in a pending purchase/detail dialog | Apply latest display precision; keep the modal and warning text/criticality intact. Confirm must revalidate owner, profile, catalog, car, cart, units, price and stock before staging. |
| Change/revert a dirty Settings or tuning draft | Draft values/dirty state remain exactly unchanged; browser preparation never saves, applies or discards them. |

For every stale case, assert rejection/cancellation, no stale fact or enabled stale action, current warning preservation, and successful latest-state recovery. Keep the exact query order and all seven comparison values/precision; assert only the current virtual card window is materialized. Include a preparation failure/retry path; a failure may not silently fall back to a complete blocking constructor and be counted as a bounded-frame pass.

## Runner and native evidence

Managed entry: `ShopBrowserPreparationChecks.Run(Action<bool,string>, string fixtureDirectory)` under a focused `RunNativeBrowserPreparationOnlyCheckpoint` route. Native entry: `--draglab-native-browser-preparation-only-verify` with the same isolated save/report fixture; use a development-only held-step gate for deterministic mutation cases. No shared S06C/S06D1 report root.

For performance, run the existing matched seed and real `RefreshParts` route with `--draglab-frame-probe` plus its isolated `--draglab-verify <reportDir>` path. Report ready-group/binding flags, preparation-step count/max and total, `ApplyPartQuery`, owner-thread publication/card cost, allocations, full `nativeParts` and `frameMs` tails through first complete list, comparison completion, and navigation away/back. Include empty and nonempty carts, Shop/Inventory/Installed, current/planned views, F8 and a resize. A later-frame spike is still a failure; source timing or a managed pass alone cannot close the native S06 gate. Parent runs Unity/native/Git and records actual outcomes after the API is frozen.
