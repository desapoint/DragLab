# S06d2b1f validation supplement

**Status:** Editor-only characterization source added; Unity compilation and execution are pending. This supplement does not change production validation, commerce, inventory, persistence, or UI behavior. It adds no typed-preview parity or freshness evidence.

## Scope

`RunValidationSupplement` exposes `validation` (all four families) and focused `validation-sales`, `validation-integrity`, `validation-stock`, and `validation-positions` scopes. Every corrupt profile is a literal copy of an already normalized fixture, and corruption is injected only after copying. The test never calls `Ensure` on an injected malformed profile. `CompareTotal` records the exact production and frozen-oracle result, source/catalog/row immutability, exception type/message, and declared earliest stage. Expected errors are pinned explicitly; valid control cases assert success.

- **Sales:** Invalid dealer handling policy is expected at `ValuationPolicy.Validate`; invalid time and the absent wholesale buyer are expected during the first sale's `DisplayLooseTotal`, after global `ValidateForQuote`.
- **Owned and dealer integrity:** Duplicate owned identity, null owned condition, and a null serialized member are injected independently and first observed during the sale's global validation. Dealer both-payloads use actual valid used-part and used-unit payloads; no-payload, negative paid price, and duplicate physical identity use a real dealer part row at its recorded index. The stale discriminator control records strict `MechanicsOwnership.Validate` failure while `ValidateForQuote` and the sale quote tolerate that discriminator-only mismatch.
- **Stock and reservations:** A null stock row exercises ledger construction before row validation. Invalid units and delivery percentage are checked on the first sale's global validation. The absent-product control removes one actual market stock row from a literal fixture, clears its nonserialized index, validates the remaining profile, and manually checks the all-express 10% amount. Reservation probes cover future generation, a hold over the current shelf, duplicate zero-unit and absent supply-row controls, and an older-generation hold that is valid but not counted as current stock. A separate basket uses the 100 highest actual eligible set prices at quantity 99 and manually accumulates actual local/express supply and rounded fees into a 64-bit expected total. Separately, a conservative bound for all new purchases uses the largest nonnegative authored part price, `max(1, price)` as a set/unit base ceiling, at most 10% express fee rounded up per purchase, and the 100-row × 99-quantity limits. If that bound is below `Int32.MaxValue`, it excludes positive-total overflow for this authored new-purchase family independent of distinct role/offer choices. It does not bound used-part/unit sales, custom policies, or later checkout arithmetic.
- **Positions and moves:** The wrong-spec case uses the existing same-model pair helper and its actual new-car listing/purchase. It retains target D1, quotes and buys an affordable distinct D2 piston set through `PartOperations.Buy(..., install: true)` on the donor, then passes one actual D2 member ID to `NewUnits(D2)` on the target; D2 must fit the target. Move cases use a real loose unit bought through `InventoryUnits.Buy` and sent to an engine destination, and two separately bought real parts of one category sent to the same car slot.

The wrong-spec position and absent-product fixtures use authored topology/catalog data. If the project does not supply their required real shape, the scope emits an explicit OPEN record and a failing precondition instead of synthesizing IDs, positions, offers, or stock. The overflow scope does not modify authored prices or supply: it uses the 100 highest-priced distinct eligible definitions and actual per-definition stock state, then records the manually derived 100×q99 total before comparing `PartCart.Total` with the `Int32` bound.
