# S02b installed binding lookup checks

S02b checks the second identity lookup family: one operation-local capture maps an owner's installed binding rows to the matching owned `PartInstance` references and slot definitions. The test harness compares the new surface and public callers with independent ordered `List.Find` scans. It uses newly authored in-memory profiles initialized through `MechanicsOwnership.Ensure`; it never reads or writes player saves, performs JSON manipulation, or clones a whole profile. Editor checks require batch mode outside Play Mode. The coordinator owns Unity execution and raw reports under `reports/save-refactor/S02B/`.

| Area | Implemented coverage |
| --- | --- |
| Lookup contract | Preserve one ordered entry for every binding, including missing identities as null; return the actual source object reference; definitions skip missing rows; blank binding IDs remain absent; null binding rows reject; duplicate categories keep the legacy `Dictionary.Add` failure; disposed lookup rejects access; empty sources and dangling rows do not fabricate records. Exercise the strict fallback when unique requested IDs outnumber source parts. A fresh capture after same-count identity replacement sees the replacement and omits the old ID. |
| Public parity | For three authored representative vehicles (petrol, diesel, and AWD when present, with authored fallback selection), compare `MechanicsOwnership.Definitions`, `MechanicsOwnership.Resolve`, and `InspectionBuild.Capture` against independent list scans. Compare ordered diagnostics, resolved vehicle/tune data and tire/wheel fitment, full typed `PartInstance` copies including identity/owner/slot/location/storage/version and member histories, and starting fuel/fluids. Verify captured component copies remain unchanged after mutating the source condition, then restore the fixture. The final fixture alters tire/member wear and selects different fitting front/rear tire-definition IDs, retaining all physical PartInstance and individual member IDs. Full resolved spec equality includes the serialized per-corner definition arrays. |
| Failure and incomplete fixtures | Compare missing/detached binding behavior against legacy scans and ensure definitions/inspection do not invent a component. Compare the detached-engine diagnostic path. Duplicate binding categories must fail through the same category-map insertion behavior. Corrupt duplicate source IDs and malformed unrequested source rows remain outside the validated-source precondition; sparse index capture may stop before such an unrequested tail, so S02b does not claim full ownership-topology validation. |
| Operation freshness | Each public call captures within its own synchronous lifetime. Bench fixtures reorder actual installed part objects among an otherwise inventory-only list before capture; no map is cached across calls. The harness does not mutate a list while a capture is alive or retain borrowed references beyond the fixture call. |
| Cost characterization | At total list sizes 100, 1,000, 10,000 and 30,000, compare legacy scan plus typed copies and the new capture plus map/copies end-to-end. Position groups put installed identities first, last, or at deterministic scattered positions. Separately time each migrated public endpoint (`Definitions`, `Resolve`, `InspectionBuild.Capture`) with five warmed repeats and report median and sample maximum only. The helper comparison excludes dyno calculations; endpoint timings include their actual work. No p95/p99, heap allocation, or complete gameplay-performance claim is made. |

Synthetic padding consists of inventory-only typed part records with unique stable IDs and is not a full gameplay profile. The authored profiles use generated entity IDs, so reproducibility is based on logical invariants rather than byte-identical profile hashes. Fieldwise equality and output comparison run outside timed intervals. The public endpoint timings are descriptive post-integration measurements; only the explicit helper comparison has an independently implemented legacy-scan timing baseline. Results are not evidence that any other command is migrated or that broader save-path requirements are satisfied.

Coordinator evidence: prior full harness revision passed 250 parity/scaling checks + 72 existing isolated storage checks, exit 0; final test-source focused parity with distinct front/rear definitions passed 220 overlapping checks, exit 0. Production/timed algorithms are unchanged between those runs. Raw receipts, actual commands, 36-row measurements, compile-failure correction and limits are in reports/save-refactor/S02B_RESULTS.md. The harness author did not run Unity. No final-source full-suite count or phone/frame claim is inferred from the focused rerun.
