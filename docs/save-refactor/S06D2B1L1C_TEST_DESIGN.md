# S06D2B1L1C — raw cart Apply test design

Status: design only. This plan covers the finite L1C0 frozen-mutator gate and the complete L1C typed projection gate described in [the L1C contract](S06D2B1L1C_CONTRACT.md). No game/tool implementation, Unity execution, build, or Git operation is authorized by this design note.

## L1C0: freeze and prove the mutating reference

L1C0 must be completed and locally committed before any shared Apply/acquisition/install helper is extracted or redirected. It freezes the committed K/L1B source and does not edit production code. The existing `LegacyCartPreviewOracle.Apply` preserves the raw loop, but it calls current `PartOperations`, `InventoryUnits`, `SharedInventory`, pricing, and installation helpers. It cannot by itself be the independent authority after any of those bodies change.

Add only the reference and checker files named by the contract: `LegacyCartApplyReference.cs` (+ metadata) and `CartApplyReferenceChecks.cs` (+ metadata). The reference copies the exact raw Apply driver and literal bodies for every currently unfrozen transitive helper it reaches. It may reuse the committed `LegacyWholePartMoveReference.ReplaceCar`/`EnsureMembers`, `LegacyWholeEngineMoveReference.Move`, K ordered Move driver, and L0/L1A/L1B frozen references where their closure already covers the exact operation. It must not call candidate state, a planned shared transition, or any live helper whose body will be modified. Record method-level provenance and hashes for the full closure, not only the Apply entry point.

### L1C0 liveness matrix

Build live and frozen-reference fixtures independently with `CartPreviewCharacterizationFixtures.CreateNormalized`; each call creates a new `MechanicalCatalog`. Never share a catalogue instance across live/reference fixtures, including cache-mutation cases. Where paired fixtures need identical IDs, literal-clone only the profile data into a second fixture and assign that fixture’s independently created catalogue. Before running either side, compare typed authored part definitions and specs, plus the initial private catalog-index state; require exact source order/value parity and equivalent cold/warm index contents. Reproduce aliases and malformed-index layouts explicitly in both independent catalogues, then verify each fixture’s index state before the operation. Do not let one side’s lookup/cache writes prepare the other side. Keep all stock/dealer/ownership setup outside measured candidate scopes. The frozen reference is intentionally mutating and runs only on its disposable profile. Compare its success graph, return/identity observations, failure type/message, and partial effects with unchanged live `PartCart.Apply` on a separately prepared fixture.

- NewSet: quantity zero, quantity two as loose stock, and quantity two with installation. The installed case must show that only the first quantity replaces the target slot, the prior root is retained with its exact condition, and the second complete set remains loose. Compare cash, local/express stock and holds, root/member identity topology, and source immutability.
- NewUnits: quantity zero and quantity greater than one; an installed engine member with selected positions and an unselected purchased extra; separately exercise actual WheelElement and TireCondition installation paths, including a real tire payload reached through the typed `LooseEngineElement.tire` accessor where the authored fixture exposes it. Record authored compatible definitions, fitted roots, role and position counts before selecting rows. No missing topology is a pass.
- BuyUsed: actual generated dealer part and actual dealer unit, loose and installed where the authored fixture permits. Verify the original item/member IDs, subtype, condition, wear/fault history and dealer wrapper removal; installation must retain displaced members in their actual append order.
- Move and ordering: use existing K actual part/engine/unit fixture helpers and the frozen K dispatcher. Include one cart sequence where an actual BuyUsed part is installed, then a later Move of that same pre-existing asset ID observes the new owner/container state. Include purchase rows before and after a Move, and a reversed order pair whose result or first failure differs. The raw loop dispatches Move once even when `quantity` is greater than one.
- No-op/raw dispatch: interleave SellPart and SellUnit rows with missing or intentionally malformed asset IDs; Apply skips both. Test unknown enum action fallthrough through the used-stock branch, empty input, zero/negative quantity, and `preview` true/false. This is raw Apply characterization; do not call `PartCart.Total` to prevalidate or cap the rows.
- Error and partial prefix: valid NewSet prefix followed by a null row; valid purchase prefix followed by a missing used asset; and a real NewUnits purchase followed by `positions == null` with install enabled. Pin the exact exception and line position from the input sequence. The frozen/live profiles must show the legacy mutations completed before the error, including cash, stock/holds, dealer rows, added items and owner bindings. Candidate input remains untouched in L1C; its failed result contains no partial output.

The matrix uses actual content only. Existing helpers provide the normalized selected car, an actual used set-only part (`AddUsedPart`), a real multi-member used row (`AddUsedUnit`), second actual vehicles, and a real detached engine. `AddUsedUnit` does not guarantee a WheelElement or TireCondition: for those cases select an actual compatible authored wheel/tire definition and use `PartsMarket.AddUsedSupply` with deterministic fixture seeds in a bounded search. Keep only generator-produced, validated actual dealer units of the required runtime subtype; remove failed search rows from the disposable fixture. Record attempted candidates/seeds and observed authored counts. If a real required subtype/fit topology cannot be produced, record the case OPEN and do not mark C0 or L1C complete. Do not fabricate physical members, IDs, wear, wheel overrides or tires.

Use `RuntimeEntropy.IdentityObservation` around the legacy Apply call to record every real ID event and correlate it with `(input row index, quantity ordinal, semantic path)` keys. Verify each generated output root/member has one unique event-derived identity, no collision with existing assets, and no missing or extra output. Existing identity diagnostics (`IdentityBuildMap`, `IdentityPhysicalIds`, and the typed graph walker) are reusable only as test helpers; the new closure must independently pin how each raw Apply branch produces records. Moves and sale skips must not acquire IDs. The fixture harness restores outer RNG state between isolated actual/reference runs and checks source/profile/row/catalogue references and values afterward.

Root runs the focused C0 Editor diagnostic only after the full source manifest is frozen, verifies no actual Editor/player is active before editing or launching another run, and records the terminal/manifest hashes. C0 passes only when the independent reference is source-complete, all required actual fixtures are live, and every liveness, identity, first-error and partial-prefix assertion passes. No candidate projection exists in this gate.

## L1C: complete ordered typed Apply differential

After C0 review and commit, implement the complete raw non-sale `PartCart.Apply` projection in one checkpoint using the proposed `OrderedCartApplyProjection.Evaluate(owner, carId, rows, policy, preview)` surface. Preserve row and quantity order with one scoped working set shared by NewSet, NewUnits, BuyUsed and Move. Keep the scope dormant; this design does not authorize a `Total`, `DeliveryFee`, quote/checkout, sale-commit, PreviewProfile, UI or live caller conversion.

Use C0's independent literal reference on a disposable fixture and the projection against the untouched input. Compare the full typed outputs against C0's final legacy graph: cash, ordered part/engine/unit/dealer/car ownership, slot bindings, storage, member/tire/wheel payloads, tune/fluids where moved, local market units, reservation rows, and ordered per-row/per-quantity effects. Canonicalize only new IDs through the complete event-derived `(row, quantity, memberPath)` bijection. Existing IDs must remain literal and attached to the same source objects/descendant facts. Compare every quote's local/express units, fee and cost and each row's exact hold/stock delta. Check output-owned arrays/nested snapshots by mutation and a fresh evaluation; candidate snapshots must contain no profile/catalog/domain-record references.

### Ordered purchase, move and skip cases

- Exercise each action in raw source order: NewSet, NewUnits, BuyUsed part, BuyUsed unit, Move, and skipped sales. Include both `preview` values and a repeated-row sequence that reuses product stock while buying different actual rows/assets. Apply performs no duplicate/cap/quantity validation. For each supported purchase branch include quantities 0, 1 and more than 1 where its semantics differ.
- NewSet with install false and true, including quantity two: first-only installation, exact displacement into inventory, and a second independently initialized loose set. Compare each per-iteration quote, cash debit and market/local stock remainder.
- NewUnits with one actual engine-element role and member identity, plus dedicated actual WheelElement and TireCondition installation cases; the real tire route is available through `LooseEngineElement.tire` when an authored tire payload is supplied. Cover quantity two with partial `positions`, position input order, the retained loose extras, exact old member return, unchanged nonselected neighbors, and all four tire/wheel corner representations where required by the target method. Preserve TireCondition subtype, definition, ID and history; preserve wheel overrides and displaced wheel identity/condition.
- BuyUsed part and unit use the original actual dealer payload. Cover loose purchase and installation; verify dealer lookup/removal order, original root/member IDs, purchase price, storage transitions, actual member subtype, wear/fault and tire history. For quantity above one, the second iteration re-finds the now-removed dealer asset and produces the legacy error after the first iteration's effects in the reference.
- A mixed ordered case places NewSet/NewUnits/BuyUsed around a Move so later queries see the private stock/dealer/car/owner changes produced earlier. Include BuyUsed-part-then-Move of that same known source asset, plus a K source-to-destination engine or unit move. Reverse an order-sensitive pair and compare exact resulting graph or first error; never sort or aggregate the rows.
- Interleave SellPart/SellUnit with purchase/move rows. They are no-op rows for this Apply projection even if the asset is absent; they do not realize sale value, add dealer stock, or fund purchases. Undefined enum values retain the exact used-row fallthrough branch.

### Supply, failure and state integrity

Use actual normalized seeded supply, then adjust only fixture market quantities/reservation rows to create bounded local-only, shortage/express, mixed-generation held, repeated-product and exhausted-stock cases. Compare one quote/Consume per Buy iteration against the L1B frozen pricing/supply closure. Exercise `usingCartReservation` true and false as supplied by the caller; Apply neither infers nor changes it. Include alias stock and sequential purchases to prove later rows see depleted private quantities. Preserve used stock’s separate BuyUsed price path.

Pin raw dereference/exception order for null row, null positions when reached, null/unknown definition, unknown used asset, invalid dealer discriminator/payload, unavailable fit/role/position, insufficient cash, and errors after one successful earlier row. Use a real topology with a deliberate bad requested position for install failure. Compare exact exception type/message and known input row index; on the frozen profile assert the actual earlier partial changes. On the projection assert no result arrays/effects/deltas on failure, no change to input values or reference identities, and disposal clears all borrowed owner/catalog/market/dealer/unit/part/transition references and virtual tokens.

Before and after each projection, fingerprint explicit named mutable fields and all reachable source-reference relationships in the fixture: inventory/list order, market index and row values, reservation generations/units, dealer rows/payload references, cash, cars/owners/bindings, engines, parts/member subtypes/condition and service history, loose units/tires, catalog source/index/revision, and input line/position values and references. Do not rely on Unity serialized reflection for readonly collections or maps. Candidate must not invoke JSON encode/decode, whole-profile clone/normalization, `MechanicsOwnership.Ensure` on the existing owner, public index/cache publication, identity generation, Unity RNG, or captured clock/entropy. Use runtime counters and identity/RNG observers as diagnostics alongside explicit source inspection, not as the sole no-JSON proof.

### Open facts that keep the gate honest

The frozen raw Apply closure can use the existing K part/engine Move references and L1B price/supply reference, but must add literal bodies for each changed acquisition/install helper named in the L1C contract. A live nested call hidden under `LegacyCartPreviewOracle.Apply` is not independent evidence. Confirm all source methods that a planned shared transition will change are present in the C0 frozen manifest before editing them.

`CartPreviewCharacterizationFixtures.AddUsedUnit` chooses the first valid multi-member used-unit shape and does not promise Tires or Wheels. The category-directed generator-seed search above is therefore required for those cases. Also confirm the existing starter fixture exposes a compatible installed wheel/tire pack and addressable corner positions. Any unfulfilled actual subtype, fit, or position case remains OPEN; do not replace it with a synthetic `EngineElement`, `TireCondition`, or desired-state snapshot.

The legacy helper may create/fill absent members on malformed records or allocate an ID for an empty displaced tire ID. Preserve those behaviors in C0's disposable legacy observation. The L1C candidate must apply the contract's explicit no-heal boundary to malformed existing source and must not generate persistent IDs; mark such a divergence explicitly rather than calling it parity. Well-formed source cases, including intentional legacy deterioration of a failed engine member during replacement, still require full typed parity.

Root owns the runner, frozen manifests, all Unity/build/Git operations and final reports. L1C completion requires the entire mandatory matrix with no unsupported/OPEN cases, L0/L1A/L1B/K/I/J regressions, exact frozen/live liveness, source hashes and Windows build; high review must approve before the local checkpoint commit. No native/device frame or downstream S06/S07–S14 completion is implied.
