# S02a owned-part identity index

Status: implemented one internal, invocation-local identity index family. Coordinator integration resolves checkpoint parts through private `ValidateCheckpointTargets`, disposes the map, then applies prepared affected values through local validated handles. The index is not a canonical profile owner, shared cache, worker snapshot, or second persistent authority.

## Frozen API and invariants

`DragLab.Domain.Mechanics.OwnedPartIdentityIndex` is an internal sealed `IDisposable` type with:

- `Build(IList<PartInstance> parts)`: scans one exact list and builds an ordinal `instanceId -> list position` map. A null list, null record, blank/whitespace ID, or duplicate ID throws `ArgumentNullException` (null list) or `ArgumentException` (invalid records/IDs) before the index is returned.
- `BuildRequested(IList<PartInstance> parts, IEnumerable<string> requestedIds)`: builds a sparse map for one unique, ordinal request set. Null inputs throw `ArgumentNullException`; blank or duplicate requested IDs and malformed records encountered during the scan throw `ArgumentException`. The requested set is enumerated incrementally and rejected as soon as its distinct count exceeds `parts.Count`, bounding request materialization by the source size. A request for more IDs than an empty source can contain is invalid; zero requests create an empty index. Missing IDs are allowed when the request count is no greater than the source count and remain ordinary misses after a full scan.
- `Count`: number of indexed owned-part records while active.
- `TryGetPosition(string instanceId, out int position)`: returns `false` and `position == -1` for a missing or blank lookup. A resolved position is checked against the current list entry and its ID. A changed list count or mismatch at a resolved position throws a stale-index `InvalidOperationException`.
- `Dispose()`: releases the bound list reference and clears the map. `Count` and lookup after disposal throw `ObjectDisposedException`.

The dictionary stores only strings and positions and copies no records/conditions or JSON. The index also holds the source list, which indirectly retains its records for the synchronous invocation; it is not a detached worker-safe value snapshot. Disposal releases that list and clears the map. It never publishes a profile. Its source list reference binds it to one exact candidate list, so it cannot be used as an index over another same-sized list. It is pure managed synchronous code and can be used against a detached private candidate on its owning worker. It must never be used to traverse a live profile from a worker.

The index is a one-operation view, not a self-synchronizing collection. The caller must dispose it before any structural list change, any `instanceId` mutation, callback, publication, or escape from the current synchronous validation/application. Count changes and a mismatched resolved entry are detected defensively, but the type does not scan the whole source on every lookup to detect arbitrary same-count mutation elsewhere. A new invocation must build from its current candidate, including after same-count replacement, reorder, add, or removal. Do not retain the map across commands based on profile revision or list count. Condition-only mutation is safe because it leaves the mapped identity and position unchanged.

`Build` is the strict whole-list variant: it rejects all null entries, blank IDs, and duplicate IDs. `BuildRequested` is the sparse variant for an already validated ownership graph. It scans from the beginning and stops when every requested ID has been found, storing only those positions. It rejects null/blank entries encountered in the prefix and duplicate source IDs for requested identities when that duplicate is encountered before the scan ends. An early stop cannot validate duplicates, nulls, or blank IDs in the unscanned tail; a missing requested key forces a full scan. The valid source identity/topology remains a caller precondition, and sparse mode must not be described as whole-list validation.

The sparse builder addresses a measured common-case regression from the strict map: at 30,000 source parts with the first 64 requested, the initial full-build-plus-lookup measurement was 2.2459 ms versus 0.1274 ms for 64 ordered `List.Find` lookups. Later-position lookups favored the full index because the scans traversed most of the list. The corrected benchmark includes sparse/full construction plus lookup and direct scans for first, last, shuffled and missing 64-ID groups across 100/1,000/10,000/30,000 source parts. At 30,000/first64 the corrected sparse median is 0.0191 ms, versus List.Find 0.1261 ms and strict full map 2.3960 ms. The prior full harness revision passed 1,375 focused + 72 storage checks, exit 0. After thermal assertions were added to the test source, the final-source preservation-only run passed 1,067 overlapping checks, exit 0; production and timed algorithms are unchanged. See the coordinator results for all workloads and limits.

## Integrated caller boundary

`ValidateCheckpointTargets` builds once for the exact candidate, validates through the map and collects matched `PartInstance` handles in checkpoint order into a method-local array, then disposes the index before mutation. Apply prepares typed affected condition/resource copies and the replacement receipt before assigning only to those validated handles. No callback or list/identity mutation occurs during capture/validation. The private handle array cannot escape the public synchronous call. Cars and run-checkpoint records still use existing scans and are outside S02a. Full validated topology remains a source precondition; the index is not a replacement for that validation.

The existing `MechanicsTransactions.Try` still deep-clones the whole profile with `JsonUtility`, and `MechanicsOwnership.Ensure` normalizes the candidate before and after the operation. S02a does not alter those paths, add further index families, or claim the save/JSON hard gates are met. Any later removal of clones, runtime JSON manipulation, or shared normalization is separate ordered work.
