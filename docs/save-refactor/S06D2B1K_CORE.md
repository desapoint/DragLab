# S06d2b1k — ordered inventory move working set

This slice adds `OrderedInventoryMoveProjection.Evaluate` for immutable ordered Move requests. It captures request references into an owned array, retains repeated assets and null rows, creates one scoped private state, and runs the existing preamble and shared `InstalledInventoryTransition` dispatcher for every row. The live `SharedInventory.Move` route uses that same dispatcher with legacy engine-member handling; the private sequence uses the reviewed projection policy. The scope covers whole parts, whole engines and loose units, without cart totals, pricing, UI, checkout, persistence, worker execution or caller activation.

The private profile overlay uses lazy copy-on-read records. `FirstCarOwningPart` scans in source order, borrows bindings for cars with no loaded overlay, and consults a loaded wrapper's current bindings otherwise. It preserves the original null behavior and later first-car-by-ID relookup. Loose unit wrappers are keyed by source record reference; the move writes only `storageId`, while final snapshots preserve unit identity, definition, price, tire flag and the copied concrete element subtype/data. Stored-engine part binding writes are included in changed engine tracking; attached-car binding changes do not claim a write to the engine's empty stored slots.

Success exports final owned, source-reference-deduplicated changed part, engine and unit snapshots plus first-affected-order car snapshots. Snapshot creation happens only after all requests. Repeated writes remain represented if later rows return values to their initial state. A failure reports exact type, message and row index only; earlier private candidate writes are discarded and all output arrays remain null. Empty requests return empty owned arrays without source/target lookups. A null request container reports `ArgumentNullException("requests")` at index -1; null rows naturally fail at their ordered dereference.
