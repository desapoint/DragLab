# S06d2b1l — non-sale ordered cart projection test design

Status: design proposal only. K is committed at `99ad759`; its high review and commit gate are complete. This document authorizes no Game/tools edit, UI/checkout activation, build, or Unity run. Freeze the independent reference closure and obtain the next implementation review/GO before source work.

This initial proposal is limited by [L review](S06D2B1L_REVIEW.md). L0 observations precede a corrected Apply-only contract; Total/DeliveryFee/Quote/Checkout conversion remains separately pending. Do not implement those routes from this draft.

## Target boundary

The next bounded projection is one non-sale, ordered cart `Apply` working set for `NewSet`, `NewUnits`, `BuyUsed`, and `Move`. The projection consumes copied immutable row values in original order and typed profile/catalogue facts; it returns an owned read-only result or an exact first error, never a `PlayerProfile`, mutable live-source record, or partially applied candidate. One private overlay must make earlier rows visible to later rows, including moves that free a slot, engine/part changes, used-stock removal, stock consumption, and new purchases. Existing identities, condition, topology, stock/holds, cash deltas, and row order are preserved.

Keep three responsibilities distinct:

1. **Cart eligibility and totals:** `PartCart.Total` remains authoritative for row limits, duplicate rules, compatibility/reputation, stock quotes, positions, post-loop conflicts, and prepared-block validation. The projection does not become a second cart validator or price calculator.
2. **Read-only preview:** compare against `LegacyCartPreviewOracle.PreviewProfile` on an isolated test copy, including current inspection/resolution. Candidate preview does not call it, `Ensure`, JSON, or a profile clone.
3. **Checkout/application:** `PartCart.Apply` and the existing transaction/checkout path remain authoritative and unchanged in this increment. Tests run the frozen mutating reference only on disposable inputs to compare final state. Do not route `Total`, `PreviewProfile`, `Quote`, or `Checkout` through the new projection.

## Freeze before extraction

Root captures and hashes an Editor-only independent reference before any live helper is extracted or redirected. It must retain the existing order and exact exception behavior, and it must not call newly shared candidate code. At minimum freeze:

- the existing ordered `PartCart.Total`, `DeliveryFee`, `Apply`, and `PreviewProfile` bodies from `LegacyCartPreviewOracle`;
- their changed or extracted transitive operations: `SharedInventory.Move`, `PartOperations.Buy`, `InventoryUnits.Buy/Install`, used-stock transfer, `PartsMarket.Ledger`/`Take`/`Quote`/`Consume`, reservation resolution, and the concrete wheel, tire, and engine-member replacement branches;
- all small row-copy/position handling used by the reference, plus the frozen I/J/K transition references where a Move dispatch reaches them.

The frozen wrapper invokes the frozen functions only. Record paths, source hashes, method closure, and the pre-edit baseline commit in the run note. Hashes are taken before code extraction; then preserve that reference unchanged for later focused and regression runs. Do not treat the live route as the sole oracle after it shares a dispatcher with the candidate.

## Identity correspondence and test surface

The legacy oracle allocates real IDs for newly purchased roots/members through `MechanicsOwnership.NewId`; those IDs are expected oracle effects, not candidate output IDs. The candidate must use a deterministic, preview-local identity namespace derived from `(request identity, row index, quantity index, member index/position)` and must never call the game identity generator. For each successful oracle run, create a bijection by walking rows and actual append/write order:

- NewSet: row → quantity instance → root → ordered members/tire corners. Identify the installed first root separately from loose later roots.
- NewUnits: row → quantity instance → selected ordered position or loose extra; bind the member output to its concrete generated element subtype and exact fitment fields.
- BuyUsed: compare real incoming IDs literally; there is no preview token for them.
- Move: compare real input IDs literally and observe displacement/owner writes in the frozen first-write order.

Assert the mapping is one-to-one, covers every new oracle identity and every candidate virtual identity, and never aliases an existing physical asset, another row, or another member. Compare typed records after replacing only oracle-created IDs with their corresponding virtual token. Do not ignore any other ID-bearing field (bindings, tire IDs, member IDs, dealer keys, owner IDs, engine parent IDs). Do not compare newly-generated raw GUID strings as parity, but do assert the candidate leaves ID-generator counters, Unity RNG state, `RuntimeEntropy` mode/clock and JSON-call instrumentation unchanged.

Proposed Editor checker entry point: `RunNonSaleCartProjection(Action<bool,string> check, string outputFolder)`. Keep typed fixture setup, frozen copies, reference normalization, mapping construction, full comparison, source/read-set fingerprinting and diagnostics outside any performance stopwatch. Candidate call windows should separately instrument only the candidate; do not pre-serialize or warm candidate inputs to hide a JSON dependency. Add source audits for JSON/profile-copy/`Ensure`/ID/RNG references. Explicitly inspect readonly outputs and dictionaries by named fields; do not assume generic Unity serialization/reflection checks include them.

## Exact order, economics and source-preservation checks

Capture the immutable rows and every consumed scalar exactly, including nullable values and ordered `positions`, before evaluation. Preserve `PartCart.Total`'s validation order: selected target lookup/rebuild guard, line enumeration and 1–100 count, policy/ledger construction, per-row action/quantity/duplicate/fit/role/position/stock handling, post-loop set-vs-unit conflict, then optional block Preview/Resolve. Keep `Total` calls and `PreviewProfile` calls on separate oracle copies because both currently perform whole-profile JSON/Ensure work; record their source effects rather than using one to prepare the other.

For accepted rows, compare `Total` and `DeliveryFee` independently against the frozen result. Verify ledger rows are consumed in original order and per-quantity rounded fees match, including same-product aliases, active current-generation holds and partial express. Compare the frozen Apply candidate separately: profile cash delta equals row-ordered actual operations, stock is decremented only by local supply, BuyUsed dealer rows are removed, moves retain/mount exact existing identities, and no preview/Total operation changes live cash/stock/dealer/reservations.

Before and after each candidate evaluation, explicitly compare source object/reference topology and all relevant values: input rows/positions; selected and affected cars; parts, engine assemblies, units and dealer wrappers; cash/reputation; market rows, alias/index state and generation; cart/reservation lines/supply/expiry; catalogue dependencies; JSON counter; identity observation; Unity RNG; entropy mode and captured clock. Include direct same-revision edits and replace-record controls in the eventual freshness/ticket phase, but do not turn this L Apply projection into a ticket or worker. An output-mutation vector changes nested returned conditions, bindings, tunes, fluids and maps, then verifies the source is unchanged and a fresh evaluation recreates the expected result.

## Known source-closure blockers to resolve before implementation GO

1. **Shared product-key semantics:** `PartsMarket.Ledger` owns a cold dictionary that maps each definition to the first matching stock row/product key. Ready-product alias maps can resolve through prepared groups. The test/reference must prove exact first-row behavior and reservation resolution across aliases, including stale/cold indexes; a warmed JSON or a candidate-only prebuilt map is not valid evidence.
2. **Supply data access:** `Total`, `DeliveryFee`, `PartsMarket.Quote`, and the mutating Buy APIs consult overlapping but not identical `Ledger`/market-index/reservation paths. Before extracting a shared key/stock primitive, capture its exact input order, first-match semantics, local/held/express math, fee rounding and writes. If the new seam cannot preserve all rows and cold lookups without a source-mutating index build, pause for a reviewed domain design rather than adding a second stock interpretation.
3. **Identity entropy:** legacy NewSet/NewUnits call `MechanicsOwnership.NewId`; wheel/tire swaps can allocate a fallback identity only for missing legacy tire IDs. Valid actual fixtures should already have concrete IDs. Any candidate call into that fallback is a hard failure; missing persisted members must be refused/preserved rather than silently healed.
4. **Representation:** wheel overrides and tire corners use separate typed definitions/conditions; tire generic shells are compatibility-only. `Part.Copy` may represent tire member arrays as the base `EngineElement[]`. Compare the owned-copy representation explicitly and preserve the concrete `TireCondition` instances/fields.
5. **Authority boundary:** `PartCart.Total` uses a separate Move-only JSON+Ensure candidate for Move validation, whereas `Apply` mutates its transaction/preview candidate sequentially. Preserve this observed split in the oracle; do not quietly make the new projection authoritative for Total or checkout. Any desired change to that behavior requires a separate reviewed contract.

If any blocker lacks an independent frozen helper or an actual required fixture, record the exact missing path/count and keep that branch OPEN. Do not weaken identity, no-heal, source immutability, order, or stock parity to obtain a green focused run.
