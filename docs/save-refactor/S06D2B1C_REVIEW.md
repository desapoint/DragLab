# S06d2b1c independent proposal review

**Decision: approve the read-only `RuntimeEntropy.NewGuid` emission observer, subject to the implementation limits below.** This approves only a test/diagnostic seam that can support the missing identity evidence. It does not approve a production cart change, planner, phase closure, or reduction of the Step 1 matrix. No code was changed in this review.

## Why this seam is needed

The current Editor identity checker uses output topology and one surplus item to identify new records. It cannot prove which of multiple otherwise identical loose roots or same-role extras came from a particular input row and quantity. The matrix requires the input-keyed mapping; it cannot be closed by dropping the indistinguishable cases or assigning output-list positions.

`MechanicsOwnership.NewId(kind)` is the central physical-ID path and formats the actual `RuntimeEntropy.NewGuid(kind)` result as `kind + "-" + Guid.ToString("N")`. A private, optional partial-void hook immediately after that actual GUID is produced can expose the returned scope/value pair without choosing, replacing, resetting, or seeding an ID. The existing identity implementation can then associate actual emissions, in domain creation order, with row/action/quantity records. Set-member IDs derived from a real new parent must be mapped beneath that parent using actual member role/ordinal or supplied position; they must not be mistaken for separate GUID emissions.

## Required implementation boundaries

- Make `RuntimeEntropy` partial and declare a private `static partial void` hook with no return/out value. The hook must receive the original scope and the exact `Guid` returned by the allocator. In both `Capture` branches, call it only after generation; on the deterministic branch, call after leaving `lock(sequences)`. Keep `MarketSeed` and the per-scope sequence code unchanged.
- Keep the hook implementation and lease API out of ordinary release builds. The unimplemented partial method must be erased by compilation when the Editor/deterministic-development observer is not included. In observer builds, it must be inactive unless an explicit lease is open. This is a test-only observer, never a runtime fallback or a normal-play feature.
- The observer may read the allocator's emitted value only. It must not call `NewGuid`, read or mutate the sequence dictionary, reseed/reset counters, substitute a value, change `Capture`, consume Unity random state, or add a delegate/callback under the allocator lock. Its collection path should only append an immutable `(scope, Guid)` value to the current lease.
- Use a thread-local capture lease with synchronous lifetime. Reject nesting and disposal from a foreign thread before altering lease state. Return a defensive snapshot/read-only view of immutable events; do not expose a mutable backing list. Capture windows must bracket synchronous domain calls only and must not span a coroutine yield. If another thread creates a physical ID, the captured event list will not explain that output; the identity bijection must fail rather than silently accept it.
- Bound storage at 65,536 events. Once full, set an overflow flag and stop recording; never throw from the observer or interrupt the real ID generation. The check must fail the observation as incomplete after the operation. Disposal clears only this diagnostic lease; it never clears the real RuntimeEntropy sequence.
- Keep the frozen oracle unchanged. Run production and oracle with separate, sequential observation leases over their already independent fixtures. Do not reseed or reset either allocator between calls. Compare the expected emission scope/order and map each run's real emitted IDs separately. Editor GUIDs and capture-mode GUIDs may differ between calls; the proof is their row-key mapping and result bijection, not equal GUID text.
- Cover more than the current single-spare fixture: at least two indistinguishable new set roots, multiple same-role new-unit extras, mixed rows with reversed order, and installed/loose destinations. Use actual authored supported fixtures, report missing shapes as `IDENTITY_OPEN`, and keep every requested common supported case in the matrix.
- For each case, assert exact key coverage by `(input row index, action, quantity ordinal, record kind, member role/ordinal or supplied position)`, nonempty and unique IDs, no collision with source IDs, and equality with every newly created physical output ID. Explicitly account for every relevant `part`, `element`, and tire/member emission; classify nonphysical emissions separately rather than dropping unrecognized scopes. Correlate set members from their actual root ID and actual physical ordinal/role. Compare complete typed outputs after aliasing only mapped generated IDs; existing IDs remain literal. Preserve strict source-mutation failures.

## Remaining limits

The proposed observer closes only the allocator-emission input-key gap if those mapping assertions pass. It does not close broader malformed/valid matrix rows, source immutability, native Move callback/cart/clock/identity-stream evidence, the 100-row/q99 coverage, typed runtime replacement, performance/owned-refresh gates, or S06/S07–S14. Native identity-stream tests must observe actual counters/state separately and must not infer zero consumption merely because the observer captured GUIDs. The diagnostic hook overhead is not performance acceptance.

The current `CartPreviewCharacterizationIdentity` file is Editor-only and still uses semantic selection for a single loose spare. Keep that source as a baseline, extend it to consume the observer events, and preserve the prior case coverage. No narrowing to only distinguishable output shapes is approved.

## Independent review of the identity/native implementation draft

Review date: 2026-10-28. Scope: source-only review of the current uncommitted identity observation, row mapper, native Candidate probe, and their integration. No Unity/Editor/player process was run by this reviewer. This is a diagnostic checkpoint only; no Step 1, S06, or implementation approval follows.

### Identity observer

The `RuntimeEntropy` change preserves allocator behavior by computing and returning the same actual GUID, leaving `MarketSeed` and sequence mutation unchanged, and observing only after generation (outside the deterministic sequence lock). The diagnostic partial implementation is guarded by `UNITY_EDITOR || DEVELOPMENT_BUILD`; in an ordinary release build the unimplemented private partial-void call is erased. The lease is opt-in, thread-local, bounded at 65,536 events, rejects nested/foreign-thread disposal before lease mutation, stores immutable scope/value pairs, and does not expose its backing list. Overflow records incompleteness without interrupting ID allocation. These are source-review findings, not a release-build verification result.

### Identity mapper blocker

The current mapper cannot complete any ordinary `NewSet` with member elements. `IdentityExpectedKeys()` adds a key for each parent-derived member, but `IdentityBuildMap()` only looks up that member key; no code inserts the actual output member ID under it. `IdentityCaptureEvents()` only maps real allocator emissions, and ordinary set descendants are derived from the parent ID without a `NewGuid` event. Consequently the final expected-key bijection fails for the authored piston/set scenarios. Populate and validate each derived member mapping from the mapped root and actual output member ordinal/role before running the bijection; continue sourcing tire-member IDs from the observed `tire` events.

There is also a compile blocker in the current mapper: `IdentityBuildMap` declares `usedPartId` but references `usedPhysicalId` in the used-part section. The parent independently reported this compiler diagnostic while running its frozen-source compile. It must be fixed before the identity source can be compiled or exercised.

Apart from those blockers, the mapper compares ordered event scopes/counts, fails closed on overflow or unrecognized emissions, retains existing physical IDs literally, and compares typed outputs after aliasing mapped identities. The physical-ID inventory includes tire conditions because they are concrete `EngineElement`s in `ComponentCondition.elements`. The malformed missing-tire-ID Apply probe is separate from Preview evidence. These source facts do not establish that the Editor run will pass.

### Native Candidate probe

The prior source-fact projection and fault-reporting gaps are mostly addressed in this draft: `CartPreviewSourceFacts` now walks the full serialized profile through the typed field canonicalizer, while `RecordFault` bounds and sanitizes exception type/message before incrementing the published count. The Candidate wrapper keeps `Total` and `PreviewProfile` in the original order and return/exception path, and Begin/Complete contain diagnostic failures.

The JSON counter assertion is still ineffective on the actual candidate path. `RuntimeDataEncodingProbe.PartConsumerJsonCallCount` accumulates `RecordJsonCall()` only while a `RuntimeDataEncodingProbe.Measure` scope is active. `NativeInventoryMoves.Candidate()` is called from the dialog destination button's `update()` callback and the dialog Add action; those paths are not wrapped in that scope. The ordinary bound `partMove` action's scope ends before destination selection. Thus the probe can report `jsonDelta=0` even when `PartCart.Total` and `PreviewProfile` execute their legacy JSON calls. Add a diagnostic measurement scope around the Candidate call or use an authoritative counter that records all calls, then keep nonzero calls strict-red.

The source-fact canonicalizer covers the serialized profile graph and separately checks catalog object identity plus `AuthoringRevision`, but intentionally does not hash authored catalog contents. Therefore it is suitable for the profile source-mutation check, not a complete catalog immutability gate under the broader Step 1 contract. Keep that evidence boundary explicit or add a read-only catalog content snapshot if it is to support the full catalog-source gate.

The native probe now asserts findings/fault deltas and requires at least one completed Candidate observation, so any recorded source, clock, random, JSON, or sequence finding remains a strict suite failure. The sequence-map unavailable sentinel is no longer accepted as stable. No callback execution, source purity, or passing native result is credited until the parent runs the isolated player.

## Native callback preflight (current `NativeCartPreviewCharacterization` release)

**Decision: do not clear the native probe preflight yet.** This is a source review, not a Unity/player result and not approval of the identity mapper that is still in progress. The native flow is useful and correctly scoped in several important ways, but three evidence gaps currently prevent its typed-source/counter contract from being trusted.

### What the source does establish

- The `--draglab-native-cart-preview-characterization-only-verify` route is wired from `Test-NativeMenu.ps1` into the verification dispatch. The coroutine requires deterministic `RuntimeEntropy.Capture` and refuses to clear a nonempty cart.
- It uses actual authored stock and legitimate `PartOperations.Buy(..., install:false)` calls to create the isolated fixture. Those buys and the explicit revision increments are reported as setup effects, not confused with preview effects.
- It exercises the actual empty-cart owned-part Move action and Storage target, Cancel, and Add callback, then a mixed nonempty-cart Move through the current legacy/null-origin detail route. It separately exercises stale origin, revision, and cart guards. Known legacy mutation is accumulated in `suiteOk` and checked at the end; the suite does not silently turn it green.
- `NativeInventoryMoves.Candidate()` keeps its `PartCart.Total` and `PreviewProfile` calls in their original order and return path. In the Win Development non-Editor guard, Begin precedes them and Complete is in `finally`; a candidate exception is rethrown unchanged. No profile clone, save, JSON reset, or allocator reset was added to this callback probe. Diagnostic exceptions in Begin/Complete are caught at the probe boundary.
- The source-only launcher has a separate `-DeterministicCapture` flag. The characterization coroutine explicitly fails when that prerequisite is absent; callers should pass both switches (or the script should make the dependency fail-fast before launching).

### Blockers before native typed-source/counter evidence is acceptable

1. **The “source unchanged” projection is not a typed whole-source snapshot.** `CartPreviewSourceFacts` records the selected physical asset, selected-car and engine IDs, cash/revision, matching definition stock/holds, dealer payloads, and cart reservations. It does not cover the other owned parts/engine elements or the full selected-car/profile graphs. The Editor baseline has already shown legacy serialization materializing nulls in selected-car fields such as tune, `garageJobId`, `customName`, and `lastPass`. A candidate can therefore change source state outside this projection while this equality still succeeds. Expand the typed read-only source facts to cover the relevant full source graph (without cloning/serializing the player profile), or label this narrowly as a partial projection and do not use it as a native source-immutability gate.
2. **Entropy, clock, and random observations are logged but not enforced.** The callback probe records JSON call delta, Unity random equality, and the private RuntimeEntropy sequence map, but the native suite does not fail when those values change. A missing private sequence field produces the string sentinel `<sequence-field-unavailable>` and can compare equal to itself. `RuntimeEntropy.UtcNow` is only recorded at suite start, not before/after each synchronous candidate operation. Add strict observation-availability and stability assertions for the preview scope as required by the contract; keep known legacy JSON activity as a red characterization result rather than waiving it. The identity observer's event capture is not a substitute for before/after authoritative counter checks.
3. **Fault reporting does not yet satisfy the bounded robust no-throw requirement.** `RecordFault` increments the monotonic counter and then concatenates an exception type and unbounded `Message` into `lastDiagnosticFault`. Formatting/accessing a hostile exception message can itself throw, the retained string is unbounded, and count publication precedes the corresponding message write. Bound and sanitize the retained text, make the catch path resilient to failures while formatting, and publish count/message coherently enough that the end-of-suite report cannot mistake a partial update for a complete fault record.

### Scope of approval

No compile/API mismatch was found in the inspected hook or native APIs. The wrapper preserves candidate result/failure behavior and executes Complete exactly once for each instrumented invocation. This is permission to continue source work and collect a diagnostic run after the above evidence gaps are addressed; it is **not** approval of a passing native characterization, the identity mapper, Step 1, a planner, S06 completion, performance, or S07–S14. The natural native callback remains distinct from synthetic/editor-only paths, and every legacy source mutation must remain a strict finding.
