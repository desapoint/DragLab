# S06d2b1i — scoped whole-part move projection tests

This Editor-only checker characterizes the dormant `WholePartMoveProjection.Evaluate` seam against `LegacyWholePartMoveReference.Move`, frozen before extraction from baseline `17c03a9`. It does not switch any cart, inventory, browser, save, or UI caller. Test isolation uses the existing literal test clone; production projection is checked for input immutability and emits no copied profile.

## Finite vectors

`RunWholePartMove(check, outputFolder)` uses the normalized authored starter-hatch fixture and actual hardware. Multi-owner cases buy a real same-model vehicle using the existing graph helper. No physical component, condition member ID, vehicle, or reservation is fabricated.

The eight successful directions are car→Storage, Storage→same car into an emptied slot, Storage→Storage across the two actual containers, car→car occupied slot, car→detached engine occupied slot, detached engine→car occupied slot, detached engine→Storage, and Storage→detached engine into an emptied slot. Fixture preparation uses the frozen transition for any initial detach/storage steps. Each vector evaluates the typed seam on the prepared input, runs the frozen transition on one literal copy, and runs current `SharedInventory.Move` on a second literal copy; both legacy outputs and exact error/success outcomes are compared. It compares full moved and displaced part values, exact transition-written `ChangedParts` IDs and deep records (including same-value writes), ordered touched-owner bindings, tune, part/member facts, car fuel/fluids and `InspectionBuild`, and detached-engine ordered slots/tune/fluids. Car inspection build output is checked against the frozen original resolver; stored-engine shape is resolved with the frozen ordered-definition helper and authoritative catalog because installed-car H resolution does not cover detached engines.

Two bounded owner-resolution edges are included: a bound part whose definition is intentionally changed to another real fitted category (so the old route removes the first matching category binding, then assigns Storage to the requested ID), and a two-actual-car duplicate owner-key graph where first-ID lookup reaches a car without the requested category. These are deliberately malformed diagnostics; no normalization/global validation follows corruption. The tests pin the exact resulting changed-record set or first error.

One further diagnostic combines a missing car fluids payload with an unrelated bound part whose owner pointer was cleared. The move must still succeed and preserve its source input; the owner snapshot reports `Materialized=false` with the explicit typed H inspection precondition. This checks that owner inspection failure cannot become the move result’s failure.

Rejected-operation controls pin first-error order for an unsettled run, unknown storage, missing asset, and invalid destination. Each checks exact type/message and verifies that the typed result publishes no partial owner or part output and leaves input values/references unchanged. Source evaluation also records JSON probe count, identity observer, Unity RNG and `RuntimeEntropy` mode/time.

An actual target `photo-session` reservation is a separate late-rejection case. The frozen path removes a fitted source part before target installation reaches the reservation guard; the test pins the exact error, the legacy loose-part partial state, and the unchanged target. The typed result must return the same error without exposing any partial graph or changing its input.

Member boundaries cover null and empty required member arrays, nonempty short and long arrays, a zero-member category with an empty array when an actual authored fixture is available, wrong member type, and an active-run guard ahead of a missing-member condition. Required missing engine members must return `Typed part move projection cannot initialize missing engine members.` before publishing effects. The frozen legacy copy is expected to synthesize members through `EngineElements.Ensure`; that difference stays an explicit no-heal requirement, not a parity pass. Existing nonempty arrays, including odd lengths, must remain unchanged. Fixture absence is recorded as `OPEN` with a failed precondition check, never a passing skip.

## Evidence limits

The tests establish only this finite whole-part transition family. They do not cover loose units, whole engines, cart multi-row ordering, market/sale effects, refresh staleness, or runtime caller conversion. Compilation, Editor execution, source-freeze hashes, and independent review are owned by the parent task. No result count or Step 1/S06 completion is claimed here.

Final harness observability uses explicitly named owner fields, including ordered definition-map key/value rows; the general Unity-serialization reflection helper deliberately omits readonly fields and dictionary contents, so it is not used as the owner fingerprint. The mutation probe changes an actual output map and readonly snapshot payload, checks the fingerprint observes those changes, then checks source preservation and a fresh evaluation. Owned expected parts use the unchanged PartInstance.Copy representation; a real tire probe records backing-array types while checking exact copied element data and subtypes. Raw source comparisons remain strict.

Engine fluid retention is covered by complete source/live-graph preservation. The engine owner snapshot does not export fluids that this transition never reads or changes; its build comparison uses the authoritative engine definitions and tune, not the car inspection path. No engine-fluid output or every optional hardware configuration is claimed.
