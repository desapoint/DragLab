# S06d2b1l1a — typed canonical value test design

Status: design only; implementation is gated on independent Luna-high review and root GO. This checkpoint proposes only two new dormant domain value types, `CartRowsSnapshot` and `PartProductValue`, plus focused Editor diagnostics. It does not change a live comparator, product key, market route, cart Apply/Total, UI caller, or S07 behavior.

## Goal and bounded implementation surface

Resolve the corrected L0 findings before any typed comparator becomes authoritative. `CartRowsSnapshot` must reproduce the effective `PartCartLine.Copy` plus legacy JSON signature equality rules, while retaining a separate raw typed snapshot for exact source/null/reference assertions. `PartProductValue` must represent ProductKey equivalence for the complete serialized `PartDefinition` payload except `id`, including its nested AWD specification graph. Product equivalence remains separate from `MarketCatalogLayout.SameAuthoredDefinition` freshness.

Only new domain files are in scope for implementation. The agreed APIs are immutable owned captures with explicit scalar fields and ordered child values:

```csharp
CartRowsSnapshot.Capture(IEnumerable<PartCartLine> rows)
CartRowsSnapshot.RawEquals(CartRowsSnapshot other)
CartRowsSnapshot.CartSignatureEquals(CartRowsSnapshot other)
PartProductValue.Capture(PartDefinition definition)
PartProductValue.RawEquals(PartProductValue other)
PartProductValue.TryProductEquivalent(PartProductValue other, out bool equivalent)
PartProductValue.TryGetProductHashCode(out int hashCode)
```

Capture must not retain a source row, definition, catalogue, or nested mutable object reference. It must not serialize or use reflection. `CartRowsSnapshot.Capture(null)` preserves the frozen `ArgumentNullException("source")` behavior; a null outer enumerable is not a snapshot value. Keep the domain value dormant: no changes to `CartReservations.SameCart`, `PartsMarket.ProductKey`, `Stock`, `Ledger`, `Held`, or any Apply/Total/caller route in L1A.

## Frozen, independent oracle closure

Before typed-value implementation, pin and hash the unchanged `PartCartLine.Copy`, default constructor/field initializers, `PartDefinition.Copy`, `AwdHardwareSpec.Copy`, and Unity serialization boundary as independent evidence. Freeze the complete independent mutating Apply closure immediately before mutator extraction, not as a prerequisite or scope expansion for L1A. L0's frozen `LegacyCartCanonicalBoundaryReference.Signature`, `SameCart`, and `ProductCacheMiss` are reusable only while their source bodies and dependencies remain unchanged. The frozen reference must not call the new value types or any helper later shared with production.

L1A tests use the frozen methods as the authority for each finite vector, and require exact exception type/message and boolean parity wherever the oracle returns a value. An exception is a separately asserted outcome, never treated as equality. Capture the full actual freshly loaded catalogue and report its observed count; do not hardcode L0's 9,296 market-index fixture count or include its synthetic aliases. Compare the **partition** induced by frozen `ProductCacheMiss` strings against `TryProductEquivalent`: equal frozen strings must map to equal supported typed values and equal supported typed values must map to equal frozen strings. `TryProductEquivalent` and `TryGetProductHashCode` unsupported results are neither equality nor inequality; they must not be ignored, bucketed, selected, or used for fallback. Unsupported self-comparison must not short-circuit to true; product comparison against a null `other` is supported and returns not-equal. Hashes may select candidate buckets only; exact product equality resolves every collision. Include a controlled collision wrapper that forces bucket collisions while delegating equality to the real `PartProductValue` comparator; do not forge equal values or matching typed results. Never log full JSON/key bodies. Capture the authored catalogue/reference set before the run and verify counts, order, values and object/nested references remain unchanged afterward.

## Cart rows: exact effective rules and probes

The typed value has two explicit views:

- **Raw capture facts** preserve the actual nullable values, null row, null `positions`, null position entries and every field value. The outer enumerable is validated at capture and null throws; source/reference identity facts remain test-only diagnostics. This view supports source preservation checks; `RawEquals` does not define cart signature equality.
- **Effective comparison value** mirrors the legacy copy/signature rules: outer null remains distinct and follows the frozen exception path; a null row compares equal to a default-constructed row; each tested nullable string field compares null and empty as equal; null `positions` is effectively an empty list; null position entries compare equal to empty strings. Row order and position order remain significant. A null row differs from a zero-quantity row. All other serialized fields compare by their exact effective value and enum/scalar meaning.

The L0 finite 13 ordinal-hypothesis mismatches are explicitly closed by these rules: five nullable fields (`definitionId`, `preparationOwner`, `assetId`, `role`, `destinationId`) in both null-to-empty and empty-to-null directions (10); null/default row in both directions (2); and null/empty-string position entries (1). Require frozen-reference and `CartSignatureEquals` results to agree for every member. Keep the null-row/zero-row negative control, null/empty positions, ordered/reversed positions, full outer row order, repeated rows, and all 11 serialized public fields.

Use independent explicit fixtures, not a baseline that may inherit defaults: for every nullable field assign both Stored and Query values in each directional pair. Preserve null rows and actual nulls in the input/raw snapshot even when the effective value normalizes them. Include null outer enumerable to assert its frozen `ArgumentNullException` behavior and error ordering; it is not a boolean comparator case. Check exact snapshot equality after evaluation, and prove both source rows/lists and output values are detached by mutating owned output fields/collections, then re-capturing the unchanged input and running a fresh comparison. No snapshot may expose a mutable array/list that can alter a later result.

## Product values: complete schema and equivalence probes

`PartProductValue` must enumerate every currently Unity-serialized field of `PartDefinition` except `id`, plus every serialized field recursively reachable through `AwdHardwareSpec` and its nested AWD/calibration specification. Maintain an explicit source-linked field inventory in the type and a test schema guard: if a serialized field is added/removed/renamed or nested payload changes without an explicit value mapping, fail the guard. Do not use reflection as the implementation or as the sole test: readonly fields and dictionaries are not reliably visible through generic Unity-style serialization checks. Do not omit fields simply because current authored data leaves them default.

The immutable raw capture retains the complete definition including its actual ID, exact source nulls, collection presence/order, concrete nested type, and floating-point bits where represented. Product equality applies only the observed `ProductKey` effective rules: the definition ID is always excluded; description null/empty are equivalent; null AWD hardware and default AWD hardware are equivalent; and positive and negative zero compare as the legacy key does. All other fields, nested fields and ordered content participate. Whenever `TryProductEquivalent` succeeds as equal, `TryGetProductHashCode` must also succeed with the same hash for both values; hash collisions still require exact equality. This comparison projection never writes effective defaults into source records and never heals or normalizes catalogue data.

First compare frozen and typed equivalence partitions over the full actual freshly loaded catalogue, reporting the observed count rather than assuming a fixture size. Add bounded, fresh-definition-reference perturbations for every top-level and nested serialized field, with assertions that changing an ordinary value changes equivalence only where the frozen oracle says it does. For each included serialized product string field (`name`, `fitment`, `brand`, `quality`, `followerInterface`, `description`, `provenance`), explicitly compare null-to-empty and empty-to-null against the frozen oracle; `id` remains excluded in every product-equivalence case. Also include ID-only changes, null/default nested objects, JSON escaping and Unicode strings, signed zero, finite adjacent floats, non-finite values and distinct NaN payloads where constructible. Record exact oracle errors for values Unity rejects or canonicalizes; do not predict serializer treatment. Required cases must return supported results; if an unsupported case occurs, fix the required type/case support before declaring L1A complete. There is no partial cart-only green checkpoint while mandatory product-equivalence cases remain unsupported.

For the authored partition check, compute private typed hash buckets and frozen-oracle signature buckets without emitting raw keys. Within each hash bucket, resolve collisions through exact supported product equality; also check that the same typed equality relation implies the same exact frozen signature and vice versa. Validate bucket counts, class counts, representative IDs, and bounded first-difference field paths only. Hash equality is never acceptance authority. An unsupported hash/equality result is a required-case failure, never a reason to omit a definition from the partition.

## Invariants and cost evidence

Before/after typed capture and comparison, explicitly compare raw source field values, nullness, reference identities for each source list/nested object, authored definition order/count, market index nullness/content/reference, cart row/list nullness/content/reference, Unity RNG state, ID/entropy counters, and observable JSON instrumentation. Re-run each comparison after mutating the owned snapshot to prove isolation. Do not rely on whole-profile JSON clones, runtime JSON parsing/stringification, reflection serialization, or broad blind reflection snapshots.

If capture/comparison cost is measured, keep a small Editor-only descriptive sample with fixed authored input and a few warmups/repeats; report operation count and median only, with diagnostics/hashing outside the timed region. No allocation/native/frame/device claim follows. The complete partition over the actual freshly loaded catalogue and mandatory edge vectors is required; do not reduce it to a sample for convenience.

## Gate and non-goals

This design closes only the canonical value prerequisite. Independent high review and explicit root GO are required before coding. L1A completion requires supported results for the full actual fresh-catalogue partition and every mandatory field/edge vector, exact frozen parity, and zero OPEN/Unsupported outcomes; otherwise the required implementation/case is repaired before the checkpoint can pass. Root then freezes sources, runs focused L1A diagnostics and required regression groups, checks complete source manifests, and verifies Editor/player exit/absence before any subsequent changes. A passing L1A does not authorize switching live equality/product keys, ordered stock overlay, Apply/Total, `PartCart.Total`, DeliveryFee, Quote, checkout, UI, native/device/performance gates, full S06, or S07. No profile mirror or runtime JSON dependency is permitted in any later active route.
