# S06b selected-profile owner checks

Baseline: `6d08bcb` (S06a) and `c49f103` (S05b). Harness entry point: `SelectedProfileOwnerChecks.Run(Action<bool,string> check, string outputDirectory)`. It creates a unique disposable output folder and exercises the actual `ProfileStore` owner and SQLite persistence paths; it does not edit player saves or use JSON as an oracle.

| Area | Independent evidence and required assertions |
| --- | --- |
| Durable owner receipt | Read actual `state_meta` facts through an independent SQLite connection. Compare committed load/new-save/reset and backup-promotion receipts against commit ID, reset generation, ledger revision, content revision and physics identity. Ordinary saves retain the actual generation; reset advances it exactly once. |
| Binding / selection | Exact loaded object and receipt admit a binding with canonical selected path, slot and epoch. A different object, changed profile revision/storage token, changed slot/path/epoch, legacy JSON fixture, incompatible or failed load, archive/reset failure and unverified dirty checkpoint cannot bind. Cached admission is a metadata-only path in `ProfileStore.CommandOwner.cs`; there is no SQLite query observer in the existing backend, so absence of SQL is also checked by source review. |
| Typed lease | Acquire before factory/capture work. While delayed, outcome-unknown, or committed-but-unhandled coordinator state is retained, save/begin-save, reset/archive, slot/load changes and checkpoint submission refuse before normalization, SQL, merge, file move, queueing or profile mutation. Preference-file save remains independent. Stale/double/early release fails; release after acknowledgement permits a fresh owner registration and lease. |
| Async legacy save | Begin captures candidate plus selected path/slot/epoch, and blocks typed admission and conflicting selection/reset/load through completion. A held pre-COMMIT writer proves Begin/Complete fencing; selection/path changes refuse until completion, which publishes only its captured path receipt. Candidate mutation and definite failure must not publish stale proof; ticket cleanup is guaranteed by the owner completion path. |
| Checkpoint proof | Dirty/unverified checkpoint invalidates the capability. Submission refusal occurs before checkpoint queue work while a typed lease is retained. Verified clean state can be registered again. |
| Post-COMMIT notification | Inject a diagnostic observer exception after a real committed SQLite transaction. The caller reports durable success and the receipt matches independently queried DB state. Pre-COMMIT failure leaves durable rows and metadata unchanged and does not falsely publish a receipt. |
| Cleanup / bounds | Every wait is bounded; deterministic schedulers release held callbacks in `finally`; restore `VerificationPath`, SQLite hooks, owner selection and cached state in `finally`; all generated databases live under the unique output directory. No worker waits on a callback queued to the owner thread. |

The harness compares durable columns and profile facts independently of the writer's returned result. It reports its passed-check count through the supplied callback and logs only after successful completion. Parent-run Unity evidence is required before any row is marked passed. This checkpoint covers dormant ownership and persistence fences; it does not claim gameplay UI activation, mobile behavior, frame budgets, or full S06 acceptance. Existing S05 migration fixtures and S06a pending-snapshot checks remain separate and are not rewritten.
