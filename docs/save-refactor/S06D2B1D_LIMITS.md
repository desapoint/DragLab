## Coverage

`CartPreviewCharacterizationChecks.RunLimitContracts(trace, subset)` accepts `limits`, `malformed`, or `all`. It checks exact zero-row and 101-row count errors; the 101-row vector deliberately repeats a real offer so row-count rejection must precede duplicate-offer validation. The 100-row case selects 100 distinct authored definitions that have nonnegative prices, meet the fixture REP, and are accepted by the current `PartsMarket.FitsAny` rule. Rows are all `NewSet`, quantity one, no install. It records the full eligible count and never substitutes fewer rows. If the catalogue has fewer than 100 eligible offers, it records an OPEN diagnostic with the count and fails the requested fixture precondition. It records current/frozen `Total` and `DeliveryFee`; on accepted totals it also runs the existing full typed output comparer and observed-ID bijection only when the aggregate total is below the legacy preview's `int.MaxValue/2` cash sentinel. Otherwise it records the sentinel, leaves that output subcheck open, and fails the requested full-output fixture precondition. The separate quantity 99 row records exact quote cost/fee, total, fee parity and identity output; quote exceptions are recorded with definition, type and message rather than swallowed. If no eligible q99 offer fits the preview sentinel, an OPEN record includes eligible count, over-sentinel count and a bounded sample of quote exceptions, then fails the requested fixture precondition. Quantity 100 records the exact row-validation exception and message. If the real authored offer needed for the 101-row vector is unavailable, it records OPEN and fails that precondition rather than showing a green subset.

Malformed cases retain the current `CompareTotal` frozen-oracle comparison and source immutability checks. They cover missing target before null-source materialization; garage-job and active-rebuild target locks; null row source/row, undefined action, quantities zero and 100, duplicate new offer; invalid unit role and null/empty/too-many/duplicate/wrong positions; duplicate move identity and undefined move destination; null dealer wrapper and null market; and an invalid reservation encountered when the first sale triggers `ValidateForQuote`. The shared real sale/move fixture buys one available authored HeadIntake through `PartOperations.Buy(..., install:false)` before the first snapshot, then retains that exact physical part for move/sale rows. The null-wrapper case appends a single null dealer row after setup and sells that part, so `ValidateForQuote` encounters the wrapper during its first sale. Known first-error type/message pairs are asserted literally. The parent-owned Unity trace captured `ArgumentNullException("source")` for a null row source and the Unity Mono null-market exception as `NullReferenceException` with message `Object reference not set to an instance of an object`; the current checks now pin both type/message pairs. The null-reference text is runtime-specific, so a different runtime may require a separately reviewed expectation update.

Normalization and no-heal evidence are assigned to the separate normalization increment. This file does not duplicate those checks or make claims about `Ensure` behavior.

Open malformed families include duplicate sell/slot order, conflicting or missing dealer payloads and stale discriminator, the complete stock matrix, block/multiple-target errors, and every remaining matrix vector. No typed projection exists in this checkpoint; therefore typed no-heal behavior is not asserted. Future typed behavior is expected to return its authoritative missing-data/validation error and leave input untouched, but this report does not present that as evidence.
