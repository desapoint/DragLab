## Source facts

The widened physical graph has 154 OPEN dispatch records. Its only project-source target names are `EngineElement.Failed.get` (five sites) and `TireCondition.Failed.get` (one site); other target names are framework/delegate calls. The current Game/Assets source has one base virtual Failed property and only the TireCondition override. Exact body/file pins are captured below.

`EngineElements.memberCategories` registers 14 concrete runtime classes: PistonElement, ConnectingRodElement, PistonRingElement, BearingElement, ValveElement, ValveSpringElement, ValveSealElement, FollowerElement, WheelElement, TireCondition, IgnitionElement, SparkPlugElement, GlowPlugElement and FuelSystemElement. All 14 declarations are sealed. `FaultAllowed(EngineElement)` and `MatchesCategory` use exact runtime-type dictionary lookup; the generic EngineElement base and unknown subclasses are not registered. The factory supplies the named concrete types for known categories and retains its generic default for other categories. A query must not use that fallback to reinterpret malformed existing members.

The nested sealed `CartApplyWorkingSet.ScopedCartCatalogRead` already implements `ICartCatalogRead`. Its FindDefinition uses an owned LookupScope; Resolve calls `MechanicalCatalog.ResolveCore` with that same FindDefinition callback; Fits uses the existing hardware-fit rule. Its Dispose clears only the owned scope/catalogue references. `ConcreteInstalledBuildInput.Inspection(ICartCatalogRead)` copies concrete captured parts, fuel and fluids and routes through the typed InstalledBuildResolution overload. These are existing dormant seams; no new implementation is implied by describing them.

`ResolveCore` sets the resolved spec's `hasInstalledParts` marker before its final return. `MechanicalStress` chooses a newly constructed catalogue when that marker is false. Independently, it manufactures simulation PartInstances from definitions when the supplied installed component sequence is null, even if the marker is true. Its constructor also calls member/clutch initialization on its private copies. Both the marker and concrete component/condition completeness therefore matter; source immutability alone is insufficient physical-fidelity evidence.
