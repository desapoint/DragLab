# S06d2b1c input-row identity characterization

**Status:** Editor-only identity evidence source and an opt-in Development/Editor observer added; not run here. This is a bounded Step 1 subset, not a characterization pass or implementation approval. The parent owns remaining wiring, Unity/Editor execution and result recording. The observer records only actual emitted GUIDs; it cannot choose, reset, seed, consume, or substitute identity/RNG state.

## Key scheme

`RunIdentityMatrix(Trace)` observes production and frozen-oracle `PreviewProfile` independently, sequentially, and synchronously on literal clones from the same untouched fixture. For every call, it compares the exact emitted `(scope, Guid)` event sequence against the input row execution order. A `part` emission maps directly to the new root ID for that row and quantity. An `element` emission maps directly to its installed-member or loose-unit ID. The observer value is converted only using the existing `MechanicsOwnership.NewId` format; it never generates an ID. Ordinary set members are checked against the authoritative `EngineElements.Ensure` rule (`rootId + "/element/" + physicalOrdinal`) and added to the row/quantity/role/ordinal mapping only when the output member has that exact ID and role. New tire sets instead emit one separate `tire` GUID for each of four corner records during final ownership normalization; those IDs are keyed by input row, quantity, and physical corner. Installed unit records are checked against their supplied destination position, including `wheel:N` / `tire:N` corner positions rather than treating those labels as prior member IDs. Every output physical ID is either a literal preexisting ID or covered by exactly one mapped generated key.

Selected cases include: a real stocked multi-member piston set, an installed unit definition, an existing used-part dealer record, mixed rows forward and reversed, three indistinguishable loose sets and three same-role loose units, retained draft positions on a loose NewUnits line (these are ignored because `install=false`), two selected install positions plus two loose extras, two rows for the same set definition (loose quantity two plus installed quantity three, in both orders), a same-definition loose set plus installed existing used unit, an actual compatible NewSet Tires quantity-two row, and four NewUnits Wheel/Tire rows with two installed corners and two loose extras. The same-definition used-unit fixture first buys and installs its actual selected market offer with `PartOperations.Buy`, then creates dealer supply for that exact definition and chooses a real installed member position; it records cash, stock, dealer-row, installed-part, and position effects before preview snapshots. Wheel/tire corner keys use the input `wheel:N` / `tire:N` positions. `WheelFitments.Install` copies the wheel and sets its `cylinder` to the destination corner with `valve=-1`; `InventoryUnits.Install` copies a tire unit's `TireCondition` unchanged, so that stored tire member keeps `cylinder=-1`, `valve=-1` even though its array index is the destination corner. The mapper checks and records this type-specific metadata along with the exact corner. The NewSet Tires case accounts for each final-normalization `tire` emission. The same-definition duplicate NewSet rows are intentionally passed directly to PreviewProfile to test row attribution; a separate `Total` check asserts the established duplicate-offer error. A separate malformed tire-member-ID probe directly compares production and frozen `Apply`: its physical scope=`tire` emission is keyed to the displaced corner and must appear exactly once in the displaced loose tire record. Existing part/member/dealer IDs are never normalized. The full typed output graph is compared after aliasing only generated ID values keyed by the mapping.

The mapper independently checks expected keys, observed scope/order, nonempty values, unique mapped IDs, no collision with any source physical ID, and equality between mapped values and every new physical ID in the result. It fails closed on overflow, unrecognized/extra emissions, missing events, untracked output IDs, or a cross-thread emission that has no matching synchronous event. Self-probes verify rejection of missing expected keys, aliased IDs, existing-ID collisions, extra generated records, and missing generated records. Observer lifecycle probes use real `PartCart.Apply` calls to exercise post-dispose reads, nested-lease rejection, foreign-thread disposal rejection, overflow without interrupting ID generation, and lease cleanup after an Apply exception.

`RuntimeEntropy.Diagnostics.cs` exists only under `UNITY_EDITOR || DEVELOPMENT_BUILD`. The partial hook runs after the real GUID result is computed; deterministic-capture calls occur outside the existing sequence lock. The thread-local lease stores up to 65,536 immutable scope/value events, has no callbacks or mutable result exposure, and never touches the allocator's per-scope sequences. The unimplemented partial method is erased in ordinary release builds.

## Limits and open work

If the actual catalog lacks a requested authored set, role, position, or dealer-row shape, that case is explicitly `IDENTITY_OPEN`; duplicate loose identities and quantity extras are never left open merely because their output records are otherwise identical. Ordinary set-member IDs derived from a parent root are accounted by parent and physical ordinal. NewSet Tire members and a displaced tire with a missing old ID each have their own explicit `tire` event key. Any other emitted scope must match a known input-row birth or fail the event proof. The malformed missing-tire-ID probe is a focused Apply path because the source is intentionally invalid; it is not counted as successful PreviewProfile behavior or a no-heal exception. This work does not close the full 100-row/q99 matrix, every tire/wheel/brake/block transaction, multi-car/detached-engine identity paths, native Move callback traces, same-revision stale probes, source immutability failures, or native frame/full-S06 gates. Known legacy JSON mutations remain strict failures.
