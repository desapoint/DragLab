# S06d2a live Parts native test matrix

This is the live UI checkpoint for baseline `0f2fa8a`. `NativePartsBrowserBuildChecks` covers managed parity and typed producer freshness separately. The native coroutine here is opt-in Windows development verification; it uses the isolated save folder supplied to `NativeMenuVerification`, real rendered `NativeParts` state, real mouse/keyboard input, and real owner-thread builder/query/window work. It does not construct a synchronous comparison browser or manufacture model, query or card output inside a timed interval.

Parent-run frame CSV and native captures remain the evidence for frame tails and are not replaced by the coroutine's timing summary.

## Scope still open

The coroutine compiles in Windows builds and has been run; it does not yet pass the complete gate. Native20408 reaches163 PASS /0 runtime errors, including physical/authored A→B→A recovery, real card activation, same-ID reopening and stale purchase/draft checks. It then stops on a held-detail fixture assertion that does not yet account for the new preparation yield. The corrected fixture waits for actual nonzero prepared work. The card fixture clears search, returns to the real top window, and requires enabled state, full viewport containment and a center hit test before sending real mouse input. It chooses an actual attached stocked card, with no punctuation-dependent search helper or direct delegate substitute for clicking. Opening, Back and reopening are measured interaction phases. Test-only profile JSON audits have a separate label held through the early frame-probe sample; all raw rows are retained and oracle cost is reported separately. Actual Parts work is not excluded.

The following remain required before accepting full live S06: naturally warning-bearing detail text/level retention through rebuild and failure (leave this fixture OPEN if no actual warning-bearing entry exists), Settings/tuning draft retention where a valid shared route exists, physical cache hit/miss/eviction and healthy-current detail reuse, card press/callback behavior after a queued event and same-ID replacement/removal, resize/scroll/detail preservation across every invalidation class, and parent-collected complete frame CSV/captures including attachment tails. Owned stale-action and detail-phase lifecycle tests are implemented but not yet run. No visual or performance acceptance follows from source-level checks. Nonempty-cart/multi-position typed preview and owned refresh remain later S06 dependencies; no JSON or full-profile-copy exception is implied.

All source mutations in this coroutine are limited to in-memory state on the isolated profile and are restored in `finally`. It does not save, stage a transaction or reverse an accepted durable action. Execution evidence is recorded separately in the live results report; human visual acceptance remains separate.
