# S06d2b1l1b — scoped market and reservation test design

Status: design only. This note covers the dormant `ScopedMarketReadSet` and normal (non-ready) Ledger scope proposed in [L1B_CONTRACT](S06D2B1L1B_CONTRACT.md). It authorizes no implementation, caller switch, Unity run, build, or Git operation. Resolve the contract/review points below before implementation.

## Boundary and frozen oracle

L1B tests only the scoped stock/reservation primitives: `Stock`, `Available`, `CartReservations.Active/Held`, normal `Ledger` lookup and remaining quantities, `Quote`, `Consume` as a private delta, `InventoryPricing.NewUnit`, and the shared `Calculate` fee arithmetic. It does not switch `PartsMarket`, `CartReservations`, `PartCart.Total`, `DeliveryFee`, Apply, checkout, UI, or save callers. The ready-product-group Ledger constructor is explicitly out of scope for this checkpoint; preserve it for a separately reviewed increment.

Before changing `Calculate` accessibility, freeze an independent literal closure for `Stock`, `Available`, `Active`, public `Held`, `Quote`, `Consume`, the normal Ledger constructor/`Find`/`Available`/`Quote`/`Take`/`Held`, `Calculate`, `InventoryPricing.NewUnit`, and cache-miss product equivalence. Include `MechanicalCatalog.Find`, `MarketCatalogLayout` behavior needed by the frozen product oracle, and the L1A copy/value boundaries with source hashes. The reference must not call the candidate read set, `PartProductValue` for its legacy equality, or the production `Calculate` body. At the candidate checkpoint, first compare frozen reference and unchanged live methods on independently constructed disposable fixtures; this establishes oracle liveness before candidate parity tests.

## Test seam and fixture rules

The candidate is a synchronous, owner-thread `IDisposable` scope over one live state. Its internal operations take the original `PartDefinition` where applicable, so null and dereference ordering are preserved; a string-ID-only API cannot model those boundaries. Product values are captured only when the legacy branch reaches product comparison. The scope may borrow profile/catalog references during evaluation, but disposal must sever them; results expose only owned scalar snapshots, stable source ordinals/identity groups, and private stock/hold deltas. No source row, list, catalog, profile, definition, or mutable collection escapes.

Use purpose-built in-memory fixture profiles containing actual authored catalogue definitions and only the market/reservation data needed for each case. Construct candidate and frozen-reference fixtures independently from the same explicit fixture recipe; do not use a whole-profile JSON clone, save/preview clone, or production profile mirror. Setup may use existing actual-content fixture factories. Keep setup, frozen-oracle work, fingerprints, and report formatting outside any future timing sample. Test-only stock/reservation rows are market data, not fabricated physical parts or component identities. Do not normalize malformed rows or repair source data to make a fixture valid.

The frozen reference may mutate its disposable fixture's nonserialized `market.index` and its `Consume` quantities. Candidate operations must not publish anything: compare explicit source field values, row/list/object references, market-index nullness/content/reference, catalogue definition/list references, and `AuthoringRevision` before and after. The private `MechanicalCatalog.Find` shadow needs a narrow, nonpublishing way to observe its starting index state and revision; it must not be implemented with `Find` or `DetachedNewSupplySnapshot`, both of which can publish/rebuild indexes. Its source fingerprint should be opaque/read-only and include identity groups for repeated row references.

## Required finite matrix

### Product resolution and `Stock`

- Cold null market index: exact ordered ID-map construction, first duplicate `Dictionary.Add` failure and message. Legacy assigns the dictionary to `market.index` before filling it, so a duplicate/null-row failure leaves the assigned dictionary with its inserted prefix; the candidate keeps that same prefix privately and leaves the borrowed market index null. After catching a construction failure inside the test, query both a prefix ID and a later missing ID before disposing the scope to pin reuse of that partial private map. Include valid empty rows, unknown definition IDs, null definition-list shape, and a null stock row to pin first error and ordering.
- Cold exact-ID hit: exact ID mapping wins over any earlier equivalent row. Cold missing-ID product lookup scans market rows and definition IDs in order, skips unknown catalog IDs, selects the first exact `PartProductValue` equivalent, caches only a found alias, and leaves a miss uncached.
- Warm index hit: existing mapping wins even when a different row is earlier or the mapping points to a later duplicate ID. A warm miss follows the product scan and only successful matches are cached. Re-run a cache miss after source state changes: the same Ledger retains its cached null, while a new Ledger may see the change.
- Reverse row order and reverse definition order to prove first-match alias resolution changes only where the real algorithm's traversal changes. Include repeated IDs in distinct rows: cold `Stock` map construction errors, while an already-warm exact-ID entry is used as-is.
- Use the complete actual fresh catalogue plus a bounded set of actual-definition aliases derived by changing only IDs. Compare frozen JSON product classes with supported L1A typed product equivalence using exact comparisons after hash-bucket selection. Never log key bodies or rely on hashes as equality.

### `MechanicalCatalog.Find` shadow and `Ledger`

The frozen default Ledger constructor is order-sensitive: it checks reservation activity, walks stock rows, initializes each row remainder, reads `definitions[0]` when active, resolves and obtains holds in row order, and only then builds the exact-ID map. Preserve that first error and all shadow lookup side effects even if the candidate delays copying quantities. The ready-group constructor is excluded explicitly.

- Test catalog lookup with a cold null index, a valid warm entry, stale part count, replaced/moved indexed value, mismatched `value.id`, duplicate IDs, null row, null ID, and authoring/list-scan mode. Compare result or exact first exception against actual `MechanicalCatalog.Find`, while requiring the shadow not to change index identity/content, part list/definition references, or `AuthoringRevision`.
- Normal Ledger exact-ID map uses assignment semantics, so later repeated IDs overwrite earlier rows. Its cold product-equivalence map instead keeps the first row per typed product class. Assert both rules separately, including an alias that has a different result from `Stock`.
- A Ledger-local `Take(..., consume:false)` decrements only its private remaining supply. Repeated `Quote`, `Available`, and `Take` calls share that remainder for aliases resolving to the same row. A fresh Ledger starts from current source units. `consume:true` reports the source stock delta but the candidate still does not publish it.
- Include no-stock, exact stock, aliases, missing IDs, unknown catalog IDs, repeated definition IDs, null/empty definition lists, repeated `NewPartStock` object references in multiple row positions, and a warm index value referring to a row object not present in the market list. Keep actual object-reference alias groups: treating repeated references as independent copied rows changes legacy remaining and consume behavior.

### Reservations and ownership/epoch semantics

- `Active` controls: no cart, version other than 1, current completed run exactly `expiresRun` (active), and the following run (inactive). `carId` does not participate in `Active`; owner matching remains outside `Held` and is not added to this projection.
- Public `Held` tests: inactive returns zero before resolving Stock; current-only includes exactly current-generation holds; all-generations includes older holds; direct requested ID and IDs contained by the resolved stock row both match. An absent stock does not create a product-alias match. Include hold order, duplicate supply rows, repeated references to the same `ReservedPartSupply` object, checked `Sum(int)` overflow, and the public overload's Stock-before-null-dereference behavior. The internal resolved-stock Held overload is outside this checkpoint.
- `Available` always subtracts current-generation held units and clamps at zero. `Quote` adds all active matching holds back only when `usingCartReservation` is true. Pin this asymmetric behavior with old/current/mixed generation reservations and both flag values; do not consolidate the two paths into one formula.
- `Consume` takes local quote units from matching reservation rows in ascending generation order. Decrement current-generation stock only for units taken from current-generation holds, then subtract any remaining local units from stock. Preserve exhausted hold rows, generations, IDs, order, and unrelated rows. Delta parity asserts every source row ordinal/identity group and its resulting unit value, not just total held quantity.
- Exercise public `Held` via `Stock` so cold index side effects are compared on the frozen fixture. Pin cart activity before/at/after expiry and generation changes without applying `Capture`, `Clear`, or UI ownership transitions.

### Quotes, fees, and checked arithmetic

- Compare all four owned `ScopedSupplyQuote` fields: local units, express units, fee, cost. Cover no stock, partial and full local supply, express-only supply, sequential quantity iterations, delivery percent endpoints, zero-price stock, new-set price, and `NewUnit` pricing for counts below/at/above the price divisor. Verify repeated Ledger `Take` across quantity requests allocates each request against the previous private remainder.
- Preserve `Calculate` validation order: available below zero, percent below 5/above 10, units below 1, negative base price, and quantity below 1/above 99. Each failure asserts the frozen exception type/message and the first failing condition.
- Preserve the actual overflow reachability. Per-unit fee conversion cannot overflow: delivery percent is at most 10 and base price is a nonnegative `int`. Accumulated fee cannot overflow before checked accumulated cost, since cost adds the same fee plus nonnegative base price on each iteration. Cost overflow is reachable and required. `expressUnits` uses unchecked accumulation and can wrap with very large valid units across repeated quantity iterations; pin it with `units=available=int.MaxValue`, `quantity=99`, and zero base price. `localUnits` reaches but cannot exceed its initial `int.MaxValue` availability on that vector. `NewUnit` clamps its divisor with `max(1,count)`; since price/result are `int`, checked conversion overflow is unreachable for finite `int` price. Test null dereference order and negative/zero/one/large count and price bounds instead of inventing an impossible overflow case.
- `Consume` must first match `Quote`, then return exact stock and reservation deltas. Test insufficient/invalid requests and ensure failure emits no partial delta and never changes the borrowed fixture.

## Source purity, lifecycle and diagnostics

Before and after every candidate capture/query/delta calculation, compare explicit named fields and references for market row order/values, definition lists, warm index entries, reservation state/list/rows, `usingCartReservation`, market generation, completed runs, catalog list/definitions/nested AWD values, and catalogue index/revision facts. Include unknown or duplicate IDs and malformed rows as observed, without repairing the source. `IDisposable` checks cover all public operations after disposal (`ObjectDisposedException`), cleared borrowed-source references, detached result arrays/collections, and mutation of caller-returned data followed by stable repeated reads.

Bracket candidate operations with `RuntimeDataEncodingProbe`, canonical key request/encode counters, Unity RNG state, and RuntimeEntropy identity/time observers. They must make no JSON, key-cache, ID, RNG, clock, or source-cache writes. Frozen reference calls run outside these scopes; counters do not claim to intercept every direct `JsonUtility` call. Diagnostics log bounded result fields, row ordinals, exception type/message and hashes/lengths only—never full JSON, definitions, product-key strings, profile state, or Unicode payloads.

## Gate and exact design decisions

The read set borrows one owner only during synchronous operations; product values and quantity overlays are lazy, and the normal Ledger constructor still performs its legacy eager row walk and first-error ordering. `MechanicalCatalog.LookupScope` is the narrow nested same-class seam for a private nonpublishing lookup; preserve existing `Find` and `RebuildIndexes` bodies. The test-only authoring branch fixture may set and restore the private authoring flag via Editor reflection, with no production authoring API. Keep identity groups for repeated stock/hold references. Ready-product-group Ledger remains explicitly excluded. Candidate outputs are owned `ScopedSupplyQuote` and position/identity-aware deltas; there is no publication step.

Pin the distinct failure publication rules: cold `PartsMarket.Stock` assigns its source market index before population, so a duplicate/null malformed entry leaves the legacy index assigned with a partial prefix; candidate keeps the same partial prefix privately and leaves source null. `MechanicalCatalog.RebuildIndexes` publishes its replacement only after a complete successful scan; candidate lookup must never publish. If any case is unsupported or differs from the frozen result, L1B remains open; do not drop it or fall back to a ProductKey string. Root owns the frozen oracle, runner, source manifests and Unity lifecycle. Passing L1B diagnostics does not activate any live caller and does not establish full Apply/Total/DeliveryFee/checkout, stale-command merge safety, durable atomicity, device/native performance, S06 completion, or S07 authorization.
