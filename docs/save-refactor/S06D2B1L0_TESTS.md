# S06d2b1l0 canonical boundary observations

`CartPreviewCharacterizationChecks.RunCanonicalBoundaries(Action<bool,string>, string folder)` is an Editor-only diagnostic over the unmodified legacy public routes. It writes `S06D2B1L0_CART_CANONICAL_BOUNDARIES.txt` as UTF-8 without BOM. The test code owns no new product resolver or production comparator. Run it only under the root-owned L0 freeze/run procedure and review its actual Unity observations before any L1 implementation GO.

## Product key

The checker compares every public `PartsMarket.ProductKey` cache-miss result and exact error against frozen `LegacyCartCanonicalBoundaryReference.ProductCacheMiss`. Each probe uses a fresh copied definition reference and asserts one public key request plus one observable canonical encode, so a warm weak-key cache cannot substitute for JsonUtility behavior. It records only key length and SHA-256. Vectors cover only-ID aliasing, scalar price, name string, enum category, nullable-description null/empty pairs, nested AWD calibration, null/default AWD hardware pairs, signed zero and NaN/positive/negative infinity. It records that `PartDefinition` and its nested AWD/calibration source declarations have no nullable array field to compare. Non-finite or nested cases that the current authored catalogue/serializer cannot exercise remain explicit OPEN/OBSERVATION entries. `MarketCatalogLayout.SameAuthoredDefinition` is recorded separately as a freshness observation; it does not define product equivalence.

The only synthetic authored data is three `PartDefinition.Copy()` aliases with distinct test IDs. No owned hardware or physical condition is fabricated. Part definitions and nested AWD/calibration references are checked after probes against their pre-call literal cache-miss values.

## Route-specific market resolution

Each route starts from a new normalized actual-content fixture with the market index deliberately cold. The alias fixture follows `ShopSupplyProjectionChecks`: an actual stocked authored definition is copied into test-only aliases; the first real stock row receives one alias and a separate labelled disposable stock row receives a second equivalent alias. The unknown alias has the same ProductKey but is not present in either row. Controlled row units are 7 and 13 to make first-row selection observable.

The report observes `Stock`, `Available`, `Ledger.Available/Quote`, and active same-generation `CartReservations.Held` separately. Vectors include direct ID, cold equivalent-alias miss, prepopulated direct index mapping, actual captured current-generation hold, and duplicate alias ID across two ordered stock rows. It logs exact selected stock row index where exposed, available units, quote cost/fee/local/express split, exact exception type/message, index nullness/count/content hash and reference-write effect. `Ledger` behavior is inferred only from its public return values; no private selected-row access is claimed. The duplicate-row case is deliberately malformed test stock and its actual result is reported without inventing a passing Unity outcome.

Every stock route checks market row/list/definition-list references and stock values. Market-referenced PartDefinition values and object/nested AWD/calibration references are checked explicitly without logging full profile/catalogue snapshots or serialized key bodies. A production index write on a cold `Stock`, `Available`, `Held`, or `Capture` path is recorded as an observed effect, not mislabeled as a read-only route.

## Reservation signature

The checker pins the current `PartCartLine` schema at 11 serialized public fields: `definitionId`, `quantity`, `install`, `preparedBlock`, `preparationOwner`, `action`, `assetId`, `role`, `destinationId`, `destination`, and `positions`. The ordered position list, null rows, row order and outer null enumerable are separate vector dimensions.

For each pair, detached stored rows become `profile.inventory.cart.lines` using the legacy `Copy()` behavior, including null-row retention and null-position-to-empty-list conversion; the query rows remain a separate input. It compares production `CartReservations.SameCart` to frozen `SameCart`, records `Signature(stored)` versus `Signature(query)` by length/hash, and reports an ordinal all-field typed-copy hypothesis as `HYPOTHESIS`/`OBSERVATION`. If either literal signature errors, the hypothesis is marked `NOT-COMPARABLE`, not as agreement or mismatch. Hypothesis mismatches remain unresolved findings, never green parity claims. Vectors cover default/zero rows, null/default and null/zero row pairs, null versus empty positions including a null position versus an empty string, ordered/reversed positions, repeated equal rows, outer row order, every individual serialized field, explicit null-to-empty and empty-to-null pairs for each nullable string field, and null row enumeration. Values and references for both stored/query rows, lists and the original reservation list are explicitly checked and restored in `finally`.

The existing serializer route is not fully represented by `RuntimeDataEncodingProbe.CurrentThreadJsonCallCount`; the report records before/after counts with that limitation and does not use zero delta as proof that no serializer ran. No performance, native frame, device, gameplay, profile-copy, or L1 acceptance claim is made. The checker itself does not mutate production source, run Unity/build/process/Git commands, or authorize production extraction.
