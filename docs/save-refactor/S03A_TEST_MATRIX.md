# S03a steady-output cache checks

The Editor-only harness compares the typed steady-output cache delegate against the authoritative `InductionDynamics.SteadyOutput` equations. It uses authored vehicle content and in-memory typed `VehicleSpec`/`Tune` inputs; it does not use JSON serialization as an oracle, edit a player profile, or clone a whole profile.

| Area | Planned coverage |
| --- | --- |
| Physics parity | Use an authored boosted vehicle as the base for naturally aspirated, turbo, twin-turbo, supercharger, twin-supercharger, and twincharged profiles. Prefer an authored diesel vehicle; if none exists, use a documented typed diesel variant. Compare cached torque and boost against direct steady-output calculation at idle, midrange, torque-curve samples, and redline. Require exact `double` parity for stored outputs. |
| Frozen capture | Obtain a delegate and mutate curve/data before its first evaluation; verify it matches the direct result captured before mutation. Repeat after a cache hit, then request a fresh delegate and compare against direct evaluation of the changed inputs. Mutate the separate factory-reference graph and verify the same frozen/fresh behavior. |
| Dependency coverage | Exercise torque curve, compression, vehicle cam bias/timing, fuel and ignition capacities, fueling, induction data, tune power, and computed induction type/size/boost/pulley. Compare exact typed-key equality and verify changes to the direct evaluator inputs alter the fresh key. |
| Excluded dependencies | Change vehicle name, chassis mass, tire friction/pressure, final drive, and `vehicle.induction` after an `InductionProfile` has captured its own `data`; verify the key/output remains unchanged. Profile cash/name do not enter the cache API or its typed input. |
| Bounded lifetime | Exceed the 512-point FIFO and 32-entry LRU limits. Verify retained counts, point hit/miss behavior after oldest-point eviction, and that an evicted delegate remains callable without reinserting its entry. Exercise concurrent managed reads from one captured delegate. |
| Cost | Record 20 alternating-order samples over an inspection-like 100 RPM grid from idle through redline for direct full-curve evaluation, capture-only, `For` plus cold full-curve points, `For` plus hit full-curve points, and held-delegate hits. Preserve raw CSV samples and summarize median/sample maximum. `For` timing includes typed capture, equality/hash and cache lookup; it is called once per curve, not once per RPM point. Do not infer allocations from an unreliable counter. |

The source mutation checks compare typed equations and results, not serialized fingerprints. Fixture content is authored and type variants are in-memory typed inputs. The parent runs `DragLab.Runtime.SteadyOutputCacheChecks.RunStandalone` in batch-mode Editor outside Play Mode and records raw results under `reports/save-refactor/S03A/`. This matrix describes intended checks; completion and measured results are recorded after the coordinator's run and independent review.
