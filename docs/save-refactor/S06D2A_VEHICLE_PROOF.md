# S06d2a VehicleListings exact positive proof

`VehicleListings.Validate` keeps its original full validator as `ValidateCore` and uses a one-entry weak bucket per actual `PlayerProfile` only to locate a candidate certificate. A hit requires exact current leaf equality and the same current catalog. Any mismatch retires the certificate before `ValidateCore` runs. A result is stored only when the unchanged core returns `null`, ready authored content is already available, a typed snapshot is captured, and a final full predicate succeeds. Invalid results and uncapturable/uncached states are never accepted as proof.

## Leaf dependency closure

The positive certificate snapshots the six `VehicleStockState` integer headers, listing order and null positions, `firstPurchasePending`, and the ordered `PlayerProfile.parts` instance-ID sequence used by the original `HashSet`. Each listing snapshot includes every `VehicleOffer` field: model/paint/listing identity, used/mileage/disclosure/estimate/inspection/starter/run/drive/condition scalars, history-note sequence, part sequence, fuel, fluids, ask/reputation/catalogue price and tune.

Part snapshots include version, all identities/location/ownership/slot fields, every `ComponentCondition` scalar, nullable clutch fields, ordered typed engine elements and their concrete runtime type, all `EngineElement` identity/health/role/cylinder/valve/severity/wear/fault fields, and all tire-specific fault, temperature, slip, distance, contact-work, consumed-life and running-time fields. Float and double values compare by exact bits. Ordered lists, null positions, array runtime type and concrete element types compare exactly. The optional snapshot supports the authored `EngineElement[]` and `TireCondition[]` array forms; another covariant element-array type simply skips proof capture and retains full validation. `PartInstance` version/identity/location fields are retained as a conservative exact leaf superset; the original validator reads a listing part's definition ID, part instance ID, condition and member elements directly and does not call `PartInstance.Validate`.

Transitive validation reads were audited: `VehicleInspection.Validate` consumes disclosure/history/starter and tire/member condition; `ComponentCondition.Validate` consumes all captured component and member state; `EngineElements.FaultAllowed` consumes the authored category and exact member type/fault; `MechanicalCatalog.Fits` and `Resolve` consume authored definitions, model spec and complete tune; fuel/fluid validation consumes every captured resource scalar. Owned `profile.parts` contributes only the ordered `instanceId` values used for listing duplicate checks.

Authored part definitions are proved on every hit with the existing `MarketCatalogLayout.ReadyContentToken.MatchesCurrent`, which compares catalog identity, authored definition references/order/IDs, semantic snapshots and authoring revision. The catalog's base `VehicleSpec` instances are private, created as copies, and returned only as detached copies by `Spec`; they have no public mutation route. No runtime reflection is used. If the ready token is unavailable, no canonical key is requested and no warmup is started; validation runs the original core.

The profile weak-table bucket is not evidence of equality across profiles. A distinct profile object always runs the core and must earn its own certificate. Proof checks use monotonic development-only core/hit counters and a pure predicate seam; counter reads never reset state. `ValidateWithoutProofForChecks` calls the unchanged core directly for the independent oracle.

The proof contains no JSON encoding, full-profile/owned-car copy, mutation-version assumption, revision-only cache or saved valuation. It does not change first-error selection or exceptions on misses. A failed exact comparison runs the full original validator, so observing B and restoring A still reruns the core. Focused runtime parity, adversarial field invalidation, first-error/error cases and cold/warm measurements are recorded by the checker owned separately; no frame-gate or final S06d2a pass is implied by this source change alone.
