# S06D2B1L1C1 — raw Apply typed projection differential design

Status: design only. This adds the complete candidate differential matrix for the single L1C production checkpoint. It authorizes no implementation, Unity run, build, or Git operation. The frozen raw `PartCart.Apply` reference and its passing C0 liveness evidence are described in [C0 tests](S06D2B1L1C0_TESTS.md), [C0 closure](S06D2B1L1C0_CLOSURE.md), and the [L1C contract](S06D2B1L1C_CONTRACT.md).

## Candidate surface and differential rules

Use the contract's proposed dormant entry point without adding a second API or a caller conversion:

```csharp
internal static OrderedCartApplyResult Evaluate(
    PlayerProfile owner, string carId,
    IReadOnlyList<PartCartLine> rows,
    ValuationPolicy policy = null,
    bool preview = false);
```

Compare the exact API inventory in [the L1C API design](S06D2B1L1C_API.md): `OrderedCartApplyResult.Succeeded`, `HasCashDelta`, nullable `CashBefore`/`CashAfter`/`CashDelta`, `ErrorType`/`ErrorMessage`/`ErrorIndex`, and success-only `Effects`, `Parts`, `Engines`, `Units`, `Dealer`, `Cars`, `Owners`, `SupplyDeltas`, and `Identities`. Each `CartApplyRowEffect` must be checked at `RowIndex`, `QuantityOrdinal`, `RequestedAction`, `Branch`, `DefinitionId`, `AssetId`, nullable typed `Identity`, `InstallTargetId`, `PaidAmount`, copied `Quote`, and per-effect `SupplyDeltas`. Candidate-created refs in `Identity` and snapshots are virtual `CartApplyIdentityRef` values (`IsVirtual`, `TokenOrdinal`, null `ExistingId`); raw request asset/destination strings are always tagged Existing, even when the string equals a private symbol. Resolve each exported virtual reference only through `Identities` by token ordinal and check its `(row, quantity, member path, kind)` mapping; never expose or return the private symbol string. Existing references retain literal `ExistingId`. Optional identity/install/price/quote fields are absent where the dispatched operation does not produce them. Treat absence of a cash read as absent data (`HasCashDelta == false` and all three cash values null), never as a zero cash delta. Positive purchase vectors must report the observed debit and its before/after values. Move and skipped-sale trace effects use `QuantityOrdinal == -1` and their respective `Branch` enum; they emit no virtual identity or cash read. Sale rows are metadata-only skip effects, with no physical/economic effect or supply delta. Zero-iteration acquisition rows have no quantity effects.

Compare the candidate result against the frozen reference's final disposable profile and ordered legacy observations. Canonicalize only newly generated physical IDs using the complete reference identity-event bijection keyed by `(row index, quantity ordinal, semantic member path)`. Existing source/dealer IDs remain literal; BuyUsed effects preserve the original payload identities. Candidate virtual tokens are deterministic within one evaluation, distinct from source IDs and sibling tokens, path-mapped to each created root/member, and never gameplay IDs. Check each effect's action/branch/ordinal and insertion order as well as final graph parity; output snapshots and all nested arrays/maps must be owned defensive copies with no source/domain references.

For every fixture, record source value and object-reference fingerprints before and after evaluation, input row/position values and references, catalog source/index/revision, market index, cash and reservation state, plus RNG/entropy/identity/JSON observers. The candidate leaves all source and input data unchanged on success and failure. A failure result has no effect/snapshot/token/stock/cash output arrays or deltas; only its success flag, exact error type/message, and zero-based row index (or the documented outer-request index `-1`) remain. The frozen reference may have the exact legacy partial prefix on its separately disposable copy. Dispose the one candidate working set on every path and verify borrowed references, wrappers, child scopes and token maps are cleared. Do not use JSON or whole-profile copying in candidate evaluation; literal test fixture copies are allowed only to isolate oracle/source fixtures.

## First-error, partial-prefix, and malformed-source matrix

Retain the C0 cases and compare each through candidate versus the exact frozen branch: null outer row sequence; null row after a successful NewSet prefix; null positions reached by an installed NewUnits line after a real purchase; unknown/missing definition; invalid role; invalid position after purchase; unavailable fit; unknown used asset; malformed dealer wrapper with both payload kinds; null dealer entry; insufficient cash; and late errors after successful preceding rows. Include null positions only when `install` reaches them, preserving raw dereference order. Pin exact exception type/message/parameter and input row index. On the legacy disposable profile, assert the already-completed prefix, including cash, quote/stock/holds, dealer removal, created/owned physical records and owner/slot changes. Candidate failure exposes no partial graph/effect/delta, leaves source and rows identical, and disposal clears the scope.

Malformed *existing* records use the contract's explicit no-heal boundary. If an exact legacy install would create missing OEM members, normalize an existing source condition, or allocate an ID for a blank displaced member, record the frozen legacy observation and the candidate's typed unsupported-malformed-source result at that ordered branch as an explicit divergence. Do not call it parity, repair the fixture, or generate a persistent identity. Keep well-formed physical cases, including intentional legacy deterioration of a failed engine member during replacement, under strict differential parity.

## L1C0 integration gaps that must remain visible

C0's Apply matrix passed, but its closure review identifies no Apply vector for part-to-stored-engine installation (`InstallEnginePartAfterStored`) or moving a part already owned by a stored engine (`RemoveEnginePart`). The frozen reference closure includes those Move branches through the reused I/J dispatcher, and standalone K has actual mixed-overlay coverage. They remain **pending as Apply integration** until the two K/I/J Move sequences in the matrix above are executed through both frozen `LegacyCartApplyReference.Apply` and `OrderedCartApplyProjection.Evaluate`. Do not state that C0 alone covered those raw Apply paths.

## Exit gate

One candidate production checkpoint contains the full non-sale Apply scope and all shared transition/catalog lookup extraction required by the L1C contract; there are no piecemeal purchase-only or Move-only production slices. The candidate remains dormant. The checkpoint is not complete until this full matrix passes, candidate/frozen vectors preserve all C0 liveness invariants, L1B/K/I/J and required L0/L1A regressions pass, all source hashes/process evidence and Windows build pass, and independent high review approves the exact commit. Any unsupported actual topology, unexplained OPEN vector, source mutation, published catalog index/revision, generated gameplay identity/RNG use, output source-reference escape, or false cash/effect data blocks completion.
