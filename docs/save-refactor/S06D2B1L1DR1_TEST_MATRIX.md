## Explicit scope limits before execution

The checker exercises the actual concrete field types present in the normalized assigned-car fixture and searches its already generated real listings and inventory for the 14 registered subtypes. It does not claim coverage for every possible gameplay model or race topology. The array-type control reuses real normalized tire members and creates only diagnostic array containers. The AWD calibration comes from an authored definition; the clutch value is a scalar diagnostic attached to a copy of an existing clutch part. The checker also does not assert every import error branch or catalog/build topology. A missing real element type is a failed prerequisite, not a skipped pass. The run must report observed fixture type coverage and all assertion failures.

The fixture has no synthetic `ReservedBuildSnapshot` graph inserted into a player profile. Hash-only slot-label behavior mutates only the disposable job’s existing binding label. A matching hash is tested before fallback status; payload bytes changed after import are checked only after an exact hash miss.

## Failure and evidence policy

Each assertion is counted independently in `checks.txt`; trace rows identify the case and observed outcome. An unhandled fixture or checker exception writes `runner-error.txt` and fails the batch. `EditorApplication.Exit(1)` happens only after report files are written. A passing R1 run is only a focused importer/comparer prerequisite; it does not close active-job query semantics or the larger L1D checkpoint.
