# S06b selected-save ownership and write fences

Baseline `6d08bcb`: S06a149+72 and independent Luna-high review pass; S05b is `c49f103`. This next S06 increment wires validated load/write metadata into a main-thread owner capability and fences competing legacy persistence while a typed operation is retained. No refill UI route is switched yet. No new schema, JSON manipulation, full-profile copy or button-time SQL query is permitted.

## Durable facts and main-owned context

Add one immutable durable owner receipt: committed storage token, reset generation, ledger revision, content revision and physics identity. A validated current load reports these from the same read transaction. A legacy write prepares these from its actual transaction and exposes them only after COMMIT, including the incremented generation on reset. Do not infer generation from a filename, assume zero after an ordinary save, or use caller-supplied content/physics instead of actual validated persisted facts. Empty bootstrap state may have no owner receipt; it cannot admit commands. Preserve existing migration/recovery/reset safeguards and original fixtures.

`ProfileStore` owns selected slot, canonical path and an in-memory selection epoch. Cache metadata around the exact existing main-owned profile reference, never a copy. The registry/context is main-thread-only and must not enter a worker. Worker inputs/results remain immutable scalar/path metadata, existing scoped command or intent, and storage receipts. Cache invalidates on slot/path change, incompatible/archive/reset failure, failed/unverified load, and ambiguous persistence/publication. Editor `VerificationPath` and debug command-line roots are real captured owner paths; legacy JSON fixtures keep functioning but never establish a typed production capability.

Capture path/slot/epoch at the beginning of a load/save, use the captured path for checkpoint merge, write and retirement, and register only if that context still matches actual selection. A fallback backup is validated on its own metadata, then registered against the promoted primary path. New-game and supported reset registration use the writer's durable receipt. A changed profile reference, revision/storage token, selection epoch/path/slot, blocked writes or an unverified dirty checkpoint must refuse typed admission without capture/planning or SQL.

## Pending work fences

Provide a capacity lease around the selected owner for the S06a coordinator. Acquire only for the registered exact profile/current versions, with no competing legacy write/checkpoint operation. Hold it before the command factory runs. Keep it through in-flight work, unknown outcome and committed-but-unhandled results. Release is legal only for the same lease after its coordinator has no retained operation; it cannot bypass S06a acknowledgement or discard a late worker. S06c will use this lease to bind admission/publication; source only the actual selected binding from this owner, never from request labels.

While a typed lease is held, legacy save/begin-save, reset/archive, slot/load changes and checkpoint submission must refuse before normalization, merge, capture, file moves, queue dispatch or mutation. Separate preference-file saves remain permitted. No ordinary UI call drains/waits for the typed operation. Lifecycle integration must respect uncertain/durable outcomes and cannot promise an arbitrary crash-time flush. These dormant fences do not by themselves audit every direct gameplay mutation; S06c must block conflicting live actions before activating UI.

Track an existing asynchronous validated legacy save from Begin through Complete; refuse conflicting typed admission and selected-slot/reset/load changes. Preserve its existing caller API where possible. A main-only bounded ticket can retain the candidate reference/context separately from the worker Task; do not place a live profile/context containing that profile in the worker closure/result. The immutable worker result carries its actual captured path/selection metadata and durable receipt. Complete validates the original candidate/context and retires only the captured path's journal. Never attach an old completion to a new selection or retire a newer slot's checkpoint. Clear the pending ticket reliably after definite completion/failure and invalidate owner proof when the outcome cannot be safely published. An ordinary UI path must not gain a new wait; existing legacy waits remain explicit later conversion debt.

Do not return false rollback merely because a diagnostic notification fails after a proven COMMIT. Keep post-durability notifications isolated and report durable metadata truthfully; before-COMMIT failure must preserve resources. Preserve settings drafts and newer preferences by registering/publishing metadata and later affected patches, not replacing the full profile with an old snapshot.
