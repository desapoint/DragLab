Status: bounded Editor execution is complete: final frozen 342 samples, independent artifact validation and final-source 9-fixture all-table rollback pass. ## Reproducible harness

Run from the repository root with the project's Unity 6000.6.4f1 Editor after closing any other Editor using this checkout:

```powershell
New-Item -ItemType Directory -Force reports/save-refactor/S00 | Out-Null
& $UnityEditor -batchmode -quit -projectPath ./Game -executeMethod DragLab.Runtime.SaveRefactorBaselineChecks.RunStandalone -logFile "$PWD/reports/save-refactor/S00/editor.log"
```

Set `$UnityEditor` to the installed Editor executable. The harness consumes the nine explicitly versioned gzip inputs in `tools/fixtures/save-refactor-s00` and refuses missing fixtures or changed normalized state. `manifest.csv` pins raw and gzip SHA-256 hashes; runtime identities were bootstrapped once and are preserved, not regenerated from seed alone. Raw generated copies remain ignored and are not required for reproduction. Outputs `baseline.csv`, `summary.csv` and `manifest.txt` go under `reports/save-refactor/S00/`.

Each operation records its first-call and five warm-call samples against fresh in-memory clones of that same profile. Definitive actions run through `MechanicsTransactions.Try` and `ProfileStore.TrySave` against an existing per-sample SQLite database under this report directory; the initial fixture save and backup drain happen before timing, then that database and its sidecars are removed after the sample. CSV rows include elapsed wall time, current-thread managed allocated bytes, SQLite rows changed, profile/stock hashes, and `MechanicsTransactions.Measurement`, `ProfileStore.SaveMeasurement`, and `SqliteStateStore.Measurement` phases. One action injects a SQLite failure before COMMIT and asserts the committed profile remains byte-identical and the transaction reports failure. The cart fixture fixes one stocked set and quotes/checks out a second set, and asserts that the express fee is positive. Actions cover fuel quote plus payment, cart quote, cart quote plus checkout, inventory enumeration, moving one owned spare, a no-op transaction to isolate clone/normalization and durable-save cost, and failed-save rollback parity.

The durable baseline deliberately measures the current `MechanicsTransactions.Try` implementation, including its full-profile JSON clone and full normalization passes. This records legacy cost for comparison; the next design must remove that full clone from routine saves rather than adopting it as the target architecture. S00 adds no production-path clone or behavior.

All operations work on synthetic objects loaded from the versioned fixture directory. The harness never calls `ProfileStore.Load` and never touches the real player save. It uses `ProfileStore.VerificationPath` only while directing each actual durable save to its disposable report-local SQLite file. CPU timing is synchronous Editor diagnostic data; it does not report UI frame delay, queue wait, or Android performance. The first per-action sample is the first sample for that action after fixture preparation in an already-warmed Editor process, not a JIT/process/OS cold measurement. Cart quote and inventory enumeration are timed directly as read/quote paths without a fake transaction; confirmed checkout and inventory move exercise the real transactional save path. Settlement is mapped to the existing finished-race coverage below because an independently valid race result needs a larger simulation fixture.

Five warm repeats are intended as a bounded diagnostic sample, not a p95/p99 estimate. `summary.csv` reports n, median, and max; raw rows remain in `baseline.csv`. Do not infer tail percentiles from this harness. Allocation counts cover only the calling thread and exclude allocations made on the SQLite worker. The manifest records Unity version, OS, processor, logical core count, RAM, target frame rate, and VSync; it does not capture device thermals, storage model, display refresh or Android behavior. Fixtures include owned cars and their fitted parts/members, loose parts, seeded parts/car-market rows, dealer stock, run/checkpoint/reward history, and used-car history; baseline run/checkpoint/reward histories are empty, and the benchmark does not scale those dimensions.

Existing suite names above are inventory, not evidence that those suites were rerun for S00. The coordinator records actual Unity invocations and outcomes after running the harness and selected gates serially.

Integration clarification: first-call is the first sample for that action in an already-warmed Editor process. Every sample has a fresh prepopulated database with setup outside the timer; warm-call repeats the action over the same pinned input, not repeated writes to one database. Read-only actions have no SQL-changed-row value; injected rollback commits zero rows. No JIT/process/OS cold measurement or total worker-allocation claim is made. The initial compile found and corrected a shadowed local and ambiguous Debug reference before any timings were collected.

The initial full run produced 342 timing rows, but its allocation API returned constant zero. Those allocation values are invalid, not evidence of zero allocations. The final harness self-checks a known 1 MiB allocation and emits unavailable/blank unless the counter advances. SQL changed rows are blank for read-only actions and zero for injected rollback. Backup temporary WAL/SHM and report-local preference sidecars are explicitly cleaned after draining workers.
