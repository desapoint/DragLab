# S06D2B1L — independent design review

**Status: BLOCK L1 implementation GO.** The non-sale ordered-Apply projection is a valid next family after K, but the current contract still conflates two distinct market-resolution algorithms and assumes typed equivalence before establishing what Unity's serialized key treats as equal. Resolve the bounded L0 characterization below first; then submit a corrected L contract for review. This is a design gate, not a request for a pre-implementation run of the new API. The L0 baseline itself must use the project’s Unity Editor because the legacy key and row equality are `JsonUtility` behavior.

## Concrete blockers

1. **`sameProductKey` has no established typed definition.** `PartsMarket.ProductKey(d)` delegates to `MarketCatalogLayout.Key(d)`, which copies a `PartDefinition`, sets only `id` to `""`, and returns `JsonUtility.ToJson(copy)`. Thus the key compares every other serialized field, including nested tuning/AWD data, under Unity serialization rules. `MarketCatalogLayout.Same` / `SameAuthoredDefinition` is a cache-freshness check, not proof of ProductKey equality: its field comparison need not collapse null/default values, signed zero, or non-finite floats the same way JSON does. A typed hash can only prefilter candidates; it cannot decide equivalence. The design must not state that an unspecified typed `ProductKey` alias relation is exact.

2. **There is no single cold-stock resolver to flatten.** `PartsMarket.Ledger.Find` builds a product-key map lazily by market-row order and definition order, retaining the first row for each key; its direct-definition `stocks` map is separately filled in constructor traversal, with later assignments replacing earlier ones. `PartsMarket.Stock` instead builds `market.index` with `Dictionary.Add` (and therefore throws on duplicate definition IDs at that point), returns an existing direct mapping first, and only on a miss scans market rows in order for the first ProductKey-equivalent row, caching that alias in the index. Warm `market.index` contents take precedence as-is. `CartReservations.Held` calls `Stock`, while `Ledger` and `Total` have their own supply and hold flow. L's current `PartsMarketProductView` and shared matching language cannot represent these path-specific precedence, writes, and failure points as one resolution rule.

3. **The proposed typed cart equality needs a literal Unity boundary.** `CartReservations.SameCart` serializes the ordered sequence of `PartCartLine.Copy()` values. Copy preserves null rows and converts null `positions` to an empty list; Unity JSON behavior then decides what equality means for null/default-valued fields and nested positions. The design's proposed ordinal field comparator is plausible but not established as equal to those bytes. Replacing this method before measuring the actual behavior can change live reservation matching.

4. **L's scope includes a partial `Total` conversion without its full price boundary.** The design adds `OrderedCartTotalProjection`, but `PartCart.Total` lazily calls `Valuations.LoosePriceView` for sales, whose delegate valuation path is still JSON/profile-copy based. A non-sale Apply overlay does not provide a complete Total implementation or justify changing that route. Keep `PartCart.Total`, `DeliveryFee`, quote, and validation on their existing implementations in L; defer Total conversion until a separately reviewed complete family can preserve sales, ledger, Move-preview, and block-validation behavior.

5. **Freeze closure is a hard prerequisite, not a documentation-only promise.** Before redirecting any live operation, capture an independent frozen closure at the committed K baseline, including the complete mutating call chain from `PartCart.Apply` through `PartOperations.Buy`, `InventoryUnits.Buy/Install`, `PartsMarket.Consume/Quote/Stock`, reservation matching/held supply, used-stock transfer, `MechanicsOwnership.Replace`/identity allocation, and each actual engine/wheel/tire replacement helper. The reference must not call newly shared helpers. Record method order, paths, hashes, commit, and prove the frozen entrypoint still reaches those frozen bodies. The current design lists most of this closure, but it does not yet provide its captured source manifest/evidence.

## Required L0 characterization before L1

Root can own one finite Editor-only diagnostic checkpoint; no production helper redirection is authorized for it. Freeze the current K source first. Capture and report these exact boundaries against the unmodified legacy methods:

- **Product key:** compare `PartsMarket.ProductKey` byte-for-byte for the existing real alias fixtures in `ShopSupplyProjectionChecks` and same-definition copies with only `id` changed. Include representative serialized-field changes for a scalar, string, enum, nested tuning/AWD value, and null/default; record signed-zero and non-finite behavior if those values are admitted by the serializer. Pin that ID is the sole intentional omission. Do not substitute `MarketCatalogLayout.Same` for the key oracle.
- **Resolver behavior:** compare `Ledger.Find`/`Quote` and `Stock`/`Available`/`CartReservations.Held` separately for cold and warm indexes: direct ID, equivalent alias miss across two ordered stock rows, pre-populated direct index mapping, and duplicate definition ID in a deliberately isolated malformed market fixture. Record selected row identity, hold subtraction, index writes/exception type and order, and unchanged source state for the proposed private resolver. This is a small path distinction check, not a broad supply matrix.
- **Reservation row signature:** freeze the actual `Lines`/`SameCart` result for null row, null versus empty positions, default row, each serialized line field, reordered positions, and repeated identical rows. Compare the proposed typed comparator against this frozen Unity result, including cold JSON-call instrumentation. No live comparator replacement before every case agrees.

L0 outcome must be a short reviewed boundary report with the observed Unity version, baseline commit/source hashes, exact selected row/error/results and unresolved cases. If Unity cannot establish a case, leave typed matching unresolved and keep L1 blocked. There is no requirement to compile an unimplemented L API as a baseline.

## Corrected L1 boundary after L0

Authorize only a private typed ordered **non-sale `Apply`** projection for `NewSet`, `NewUnits`, `BuyUsed`, and `Move`; sale rows are skipped exactly as `PartCart.Apply` skips them. Keep the frozen mutating Apply oracle separate. Do not add or redirect `Total`, `DeliveryFee`, `PreviewProfile`, Quote, Checkout, UI callers, or ticket/freshness routes in L1. Preserve Apply row/quantity mutation order, candidate-private prefix disposal, virtual new identities, actual used identities, and source immutability.

After L0, amend the contract to expose distinct route-specific resolution seams where the frozen call graphs differ (not one invented universal stock lookup). Carry the exact serialized product equivalence relation from L0 into an exact comparator or use a collision-safe bucket plus field/serialization-equivalent confirmation. Keep existing live `Stock`, `Ledger`, reservation, and line-signature behavior until a shared seam is proven against the frozen baseline.

Once that corrected contract is reviewed and source hashes are captured, implementation and its new-API differential suite may proceed. The focused evidence should compare the private Apply route to the frozen `Apply` result on disposable copies, then run existing K/J/I/H/Parts regressions and the build under root's source-freeze ownership. Neither L0 nor L1 closes full S06, native/device/frame acceptance, checkout, or S07.
