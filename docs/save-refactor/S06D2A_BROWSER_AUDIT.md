# S06d2a browser latency audit

Audit scope: source-only design proposal after the Shop readiness and supply-projection checkpoint. Captured native navigation remained over budget at about 89 ms in the Parts consumer: current inspection 6.8 ms, Shop population 55.8 ms, and first visible card rendering about 27 ms. The complete consumer frame was still slower than the S06 gate. No performance pass is claimed here.

## Synchronous work and boundaries

`NativeParts.RefreshParts` in `Runtime/NativeParts.cs` synchronously creates `NativePartBrowser`, applies the query, and builds the visible card window on page change. The browser captures current inspection, builds entries and ownership, and classifies compatibility/warnings. Preserve exact representative/aliases, `CounterIndexed`/`Fits`/`Count`, `Ledger` quotes/holds, used prices and entry values. These profile/callback operations stay on main; moving the whole constructor to a later frame only moves the hitch.

Card creation (`CreatePartCard`, `UpdatePartCard`, `RenderPartWindow`) creates UI Toolkit elements and `RacingSurface`s on main. `ApplyPartQuery` also filters/sorts the whole section; measure it before expanding scope. Keep the existing 3 ms comparison budget, all seven deltas, warnings and authoritative inspection results.

## Smallest exact preparation/publish design

Add a `NativePartBrowserBuild` state owned by the Parts shell. Capture typed inputs in bounded slices, keep entries private, and advance by offer/classification entry under a measured 2–3 ms soft budget plus item cap. Measure max capture, prepare, classify, validate and publish steps separately. Split costly counter/quote/classification loops at exact candidates/rows; do not defer the whole constructor or catalog loop.

Use existing ready groups, `CounterIndexed`, `Ledger.BindReadyProductGroups`, `Fits`, `Count`, `Classify` and `CarInspection` as source of truth. Keep live ledger/holds on main. Start from an opaque ready-snapshot identity; validate current definition keys and mutable inputs in bounded build slices. The current strict `TryReadyShopProductGroups` costs about 7 ms and is a baseline, not a 2–3 ms step. Before atomic publication, compare the full same-revision public mutable read set without yielding; measure that maximum tail (including strict readiness if it remains in the path). Direct edits to public fields mean refs/revisions cannot replace this exact compare. Do not claim it is bounded by the prep-loop budget. Publish only the complete model and warnings.

`InspectionBuild.Capture` and `CarInspection.PrepareCar` stay on main: both read/resolve authored catalog data. If useful, pass the detached source and already prepared `CarSimulation` to a worker for only `CarInspection.CalculatePrepared(source, mainPreparedCar, runProbe:false, steadyOutput:null)`. Never call `PrepareCar` on a worker or pass profile/catalog, Unity/UI objects, preview callbacks or actions there. This retains exact curves/stats/warnings. First bound the 55.8 ms population and 27 ms card phases; current inspection measured 6.8 ms.

Build the existing visible card window on main in a few-card/2–3 ms soft budget, keeping spacers, fields, styles, IDs and handlers. Keep previous critical warning text visible with an “updating” state and disable stale card actions until atomic replacement. Query, filter, sort, section, scroll, detail or unit changes are presentation state: capture a separate presentation generation, then apply its latest values at publish so changing units/query does not rebuild model data. Preserve selection/scroll/detail if the entry still exists. Measure whole-card cost and cap per-step count.

## Request token and stale-result fence

Replace the `partsContextKey` string in `RefreshParts` if it gates this asynchronous/incremental work; it currently concatenates JSON for shared units and cart lines. Use a typed `NativePartsRequestToken` captured and checked on the main thread. It should include:

- Capture owner context on main with `ProfileStore.CaptureSelectedContext(out slot, out canonicalPath, out epoch)` (read-only and works with dirty legacy proof), plus profile/catalog refs and revisions, selected car and model-data request ID. Never call it on a worker or mutate binding. Keep model-data token separate from presentation generation (shared units/query/window).
- Compare ordered typed cart-line copies (all IDs, action, quantity, install, owner, positions). The model read set includes selected-car tune/fuel/fluids/installed IDs and conditions; owned-part/loose-unit IDs; market seed/generation/stock row IDs, units, fees; reservation clock/car/generation/supply; dealer IDs/definitions and captured prices; cash/reputation; reference map/spec. Include same-revision direct edits; profile revision alone is insufficient.
- Capture the ready-group snapshot identity. Validate catalog and other unversioned mutable values in bounded chunks during preparation, then do the exact typed final compare without yielding before publication. The current 7 ms full `TryReadyShopProductGroups` call is the tail-cost baseline; if it remains the final check, include it in the largest-step and full-frame results. References/revisions alone are insufficient; no JSON freshness token.

On any fence mismatch, discard private work and restart. Keep prior critical warnings visible with an updating state, and disable stale card actions until replacement. Before a card action stages or confirms, re-resolve entry/asset IDs and recheck current owner/profile/catalog/car/cart/unit state and current price/stock; never use captured stale price or authority. Measure capture, each preparation slice, final compare/readiness, publish, query/filter/sort, and first-card construction separately; report the maximum indivisible tail and whole navigation/completion frame. The final exact compare may exceed the preparation budget, so responsiveness depends on measured timings, not the nominal slice target.

## First implementation prerequisite: typed model read set

Before the builder, define `NativePartsRequestReadSet.Capture(profile, page, orderedCartLines, units, ownerContext)` and `MatchesCurrent(...)` as explicit runtime C# DTOs in `NativePartsReadSet.cs`. The caller captures on main; equality is hand-written field-by-field over the bounded DTO, with ordinal string/null and ordered-list semantics. Reuse existing typed `Copy()` methods where available. Do not use reflection, boxing, generated JSON, `JsonUtility` keys, or a whole-profile copy in the empty-cart Shop path. Code generation is unnecessary for this small fixed schema; if later introduced, require generated runtime/AOT output and an editor schema guard before replacing the explicit comparator.

The read set is page-scoped. Always include owner slot/path/epoch, profile and catalog identity, selected car identity/model, and exact unit preferences (`version`, speed, pressure, torque). For the inspected car include the values that feed inspection/resolution: tune, fuel, fluids, installed slot order/IDs, each installed part's relevant condition and unit identity, and the resolved definition/spec inputs. Shop additionally includes only owned definition IDs used for offer ownership, dealer rows/prices used for used offers, relevant inventory stock/reservations/market rows, cash/reputation, and the completed shop-group snapshot. Do not include wear of unrelated cars or copy every profile part's mutable payload for Shop: unrelated condition is not read by this page's population/classification. Inventory/Installed add the relevant displayed assets, their condition/unit payload, location/ownership and price inputs. Cart lines are copied in order with all action, asset/definition, quantity, install, owner/destination, role and positions fields; any preview inputs consumed by a nonempty cart belong to that typed projection too.

Catalog grouping has its own source snapshot. Keep the captured key snapshot identity and catalog reference, then validate every definition in bounded steps against the exact authored product semantics, including nested AWD hardware/calibration fields and nulls. Completion publishes immutable group/alias metadata only if the same key snapshot is still current. At the final same-frame fence, compare current values against the captured typed read set and the validated catalog snapshot; revision/ref equality alone cannot detect direct edits to public mutable fields. Measure the full worst indivisible capture and final comparison/readiness separately from the 2–3 ms soft preparation slice; do not average the final tail into that budget or assume its maximum is 3 ms. Current strict group readiness is roughly 7 ms, and any retained full readiness scan counts in this tail. A larger measured tail is a blocker to the responsiveness gate, not permission to weaken freshness.

The smallest source change surface is `Runtime/NativeParts.cs` (replace JSON context-string invalidation and own builder/presentation generations), new `Runtime/NativePartsReadSet.cs` (page-scoped typed DTO/capture/equality), and `Runtime/NativePartBrowserModel.cs` (consume captured facts in bounded construction). `NativePartPreviewCache.cs` and `NativePartSpecificationCache` paths need separate typed-key conversion before claiming no JSON in converted flows. Nonempty-cart readonly preview remains a required S06 prerequisite described below; it cannot be represented as a fast empty-cart case.

## Explicit legacy scope and remaining JSON debt

For nonempty carts, `NativePartBrowser` serializes preview context and calls `PartCart.PreviewProfile`, cloning the full profile; `PartCart.Total` can also clone for prepared-block validation. Do not move these operations to a worker or exclude their latency from S06. Before the responsiveness gate passes, add `PartCart.PreviewReadOnly(profile, car, typedLines) -> InspectionBuild`: factor existing apply/validation order over a private typed projection containing the target car, installed components, line-addressed part/unit/dealer assets, definitions, stock/reservations and resolved spec. No whole-profile clone, JSON or duplicated cart/fitment formulas. Atomic checkout remains S07. Verify exact parity against legacy preview first; keep this nonempty-cart path in S06 responsiveness measurements until integrated.

`NativePartPreviewCache.CarSignature`/`Key` and `NativePartSpecificationCache.Get` still use JSON. Replace these in converted work with typed read sets or exact `PartSemantics.Stats` computed once per validated request. Do not claim no-runtime-JSON is complete while these paths remain.
