# S06D2B1 core cart-row fixture blueprint

**Status:** Read-only implementation notes. These are proposed next characterization cases, not tests run or a Step 1 pass. The parent-owned repeat Editor run is separate from this note. Do not change production code, waive source-mutation failures, or treat this blueprint as permission to start the typed preview candidate.

## Fixture rules and available APIs

Use the Editor-only `CartPreviewCharacterizationFixtures.CreateNormalized(out PlayerProfile profile, out string carId, uint seed)` for every independent baseline. It returns the real selected `starter-hatch`, authored catalogue, full global-validation pass, and one real used part. It calls `MechanicsOwnership.Ensure` only during fixture creation. After creating a case, use `CartPreviewLiteralTestClone.Copy` to make separate equivalent inputs for `PartCart` and `LegacyCartPreviewOracle`; do not call `Ensure` to repair a case after deliberate mutations. Use `CartPreviewCharacterizationFixtures.FixedNowTicks`, `ValuationPolicy.Defaults()`, and actual returned IDs. Capture `UnityEngine.Random.state` and the source graph around each comparison; never reset or seed the authoritative identity stream as a test shortcut.

Existing helpers:

- `FindOffer(profile, car, category, unit)` chooses a compatible authored definition by price then ID. With `unit:false`, it requires a market row explicitly containing the definition. With `unit:true`, it requires at least one modeled role.
- `StockShape(profile, definition)` reports the actual `NewPartStock.units`, `initialUnits`, `deliveryPercent`, `market.generation`, and equivalent definition IDs.
- `AddUsedPart(profile, idPrefix, ref seed)` and `AddUsedUnit(...)` call real `PartsMarket.AddUsedSupply` and return the actual `DealerStock` that has the requested payload. `DealerStock.Id`, `DefinitionId`, `IsPart`, and `IsUnit` are the identity/type surface; retain its physical part or `unit.element` object and condition as expected lineage.
- `InventoryUnits.Count`, `Roles`, and `Positions` derive cardinality and fitted positions from the current car/catalogue. `Positions` is available only where that exact definition is installed; wheel/tire positions use `wheel:0..3` / `tire:0..3`.
- For a deliberately targeted used-unit installation, do not assume `AddUsedUnit` selected a definition already installed. Select a compatible installed pack and role first, then call actual `PartsMarket.AddUsedSupply(profile, InventoryUnits.Spec(profile, car, definition), definition, prefix, ref seed)` on an isolated fixture until the appended dealer row is a valid `IsUnit` with the exact installed `definitionId` and role. Bound the search and fail/open if authored supply cannot provide it; do not fabricate or rewrite the unit.

For successful preview/apply, compare a typed whole-graph snapshot plus ID bijection keyed by input row index, action, quantity index, produced record kind, member role, and position. Keep identities already present in the source literal. Independently assert the listed contract; copied-method parity alone is not the expected result.

## Exact capture protocol per case

1. Start a fresh fixture with a distinct fixed seed; record `carId`, actual catalog definition IDs, stock row index/fields, market generation, `profile.cash`, `reputation`, owned part/unit IDs and exact condition graph before creating rows.
2. Make row inputs using exact existing IDs or the helpers above. Record each full field (`action`, `definitionId`, `quantity`, `install`, `role`, `assetId`, `positions` in input order, `destination`, `destinationId`). Never substitute a new random ID for an existing physical identity.
3. Compute an independent expected result from the documented arithmetic/first-error contract. Then run `PartCart` and the frozen oracle from separate `CartPreviewLiteralTestClone.Copy` inputs. Fix `now` and policy; record both exceptions, exact integer total/fee, output typed graph and ID-bijection result.
4. Verify source graph, catalog, row objects/list order and Unity random state after each read-only operation even when legacy behavior fails that invariant. Preserve failures as red findings. For Apply, compare expected mutation on separate copies and require the input baseline untouched.
5. For successful purchases, capture the generated identity stream before/after without mutating or resetting it if the available check surface allows. An Editor pass does not close the native capture-stream gate.

This blueprint supplies candidate concrete rows; it does not close the source-invariance failures already observed or authorize a production change.
