# Rendering

DragLab uses **URP 17.6.0 / the 2D Renderer** on Unity 6000.6.4f1. The pipeline and renderer assets live in `Game/Assets/DragLab/Rendering`. Graphics and all six Quality levels reference the same pipeline. It uses Render Graph, native render scale, two-sample MSAA, the existing Gamma color space, and no HDR, post-processing, camera depth or opaque copy textures.

The current art is unlit. Cars, track sprites, lamps and tire smoke explicitly share the resource `Rendering/SpriteUnlit`, using Unity's URP Sprite Unlit shader. A serialized material reference keeps the shader in packaged players; do not restore implicit Built-in sprite materials or rely only on `Shader.Find`.

The asphalt and starting/finish ribbons use `Rendering/VertexUnlit`. Its small URP shader preserves mesh vertex colors, texture UVs, transparent blending, two-sided geometry and sorting without writing depth. Unity's standard Mesh2D Unlit shader does not preserve the existing vertex shading and has different depth/culling behavior. Material instances retain their generated textures; shared sprite materials must never receive per-object texture or tint mutations.

Native UI Toolkit geometry/text and legacy IMGUI remain their existing interfaces. Debug bench plots remain intact. This migration adds no new visual theme, lighting effects, camera framing, physics, audio or save format. Crisp 4K UI still uses the existing panel scaling/render-target approach; it does not turn source car sprites into new 4K artwork.

There were no authored lights, lightmaps, reflection probes, PPv2 profiles, custom fullscreen effects or replacement-camera shaders in the three build scenes. Their cameras and world artwork are created at runtime. Unity's generated default Volume profile contains framework defaults; it is not an authored effect stack, and the current cameras do not enable post-processing.

`DragLab.Editor.RenderPipelineMigration.Verify()` re-reads the saved pipeline, renderer, materials, quality assignments and scene dependencies. Reassess this check when adding lighting, probes or effects. The authored assets and their `.meta` files must remain versioned.

For the migration's capture coverage and limitations, see [the report](../reports/render-pipeline-20261016/CHANGES.md). `tools/Capture-RenderPipelineInterfaces.ps1` captures isolated test players; `tools/Compare-RenderPipelineImages.py` uses Pillow/NumPy for same-size overlays, amplified differences and a review index. Matching images are never resized, registered, masked or normalized to conceal changes.

References: [Unity's 2D shader compatibility](https://docs.unity.com/en-us/engine/6000.5/manual/unity2d/2d-urp/2d-renderer-urp-features/shader-compatibility), [URP migration workflow](https://docs.unity3d.com/Manual/urp/upgrading-from-birp.html). Installed package source is the authority for the APIs used here.

## Automatic image validation

Run `tools/Test-RenderPipelineImages.ps1 -Python <python-executable>` after captures. It validates the PNGs directly, then refreshes the comparison gallery even when the gate fails. Pillow and NumPy are required. The default inputs are `reports/render-pipeline-deterministic-20261016` and `tools/render-pipeline-deterministic-contract.json`; use `-CaptureRoot` and `-Contract` for another explicit baseline. The original migration evidence and its historical contract remain unchanged.

The versioned contract lists every expected capture, its dimensions, the before-file SHA256 and required suites. Missing images (even on both sides), extra captures, changed baselines, absent/failed reports, resized images and new magenta pixels block the gate. Fixed full-frame and overlapping 32-pixel tile budgets catch global tint shifts and small disappearing controls. No registration, masks, resizing or automatic rebaselining is used. The original overlays remain unmodified. The baseline fingerprints identify historical evidence; they do not imply user design approval.

Exit **0** means numerical PASS within the documented budgets; **1** means FAIL (image delta or invalid evidence); **2** means REVIEW (only declared nonrepeatable comparisons remain). REVIEW also blocks automatic acceptance. A dynamic declaration never excuses missing/invalid captures, resizing or magenta. Thresholds are explicit in the contract, not learned from whatever changes happen to be present. FAIL flags a difference, not a proven gameplay defect. Small changes below the budgets remain a limitation of tolerance-based checks.

Results are in `validation/index.html`, `validation/results.json` and `validation-matrix.csv`. The main gallery includes verdicts, allows searching for PASS/FAIL/REVIEW and supports direct capture links. The initial run and remaining repeatability limits are recorded in [the validation report](../reports/render-pipeline-20261016/AUTOMATIC-VALIDATION.md). A full green gate requires the same market data, simulation tick, completed estimates, mouse position and animation phase in both captures; broadening budgets or suppressing regions is not a substitute.

## Deterministic capture protocol

Use `tools/Capture-RenderPipelineInterfaces.ps1 -Phase before -Deterministic -PlayerPath <built-in-player>` and then the corresponding `-Phase after` with the URP player. Run these serially in an unlocked desktop session; native input probes require foreground ownership. Both players must be built from the same capture-instrumented source with `RenderPipelineMigration.BuildBaselineSurvey(destination)` / `BuildUrpReview(destination)`. The baseline builder restores the saved URP assignments after building. Default capture seeds are shared snapshots under the original migration report; their hashes are recorded in the deterministic report. Preserve them when reproducing that exact baseline.

The capture flag activates only in Windows development players with an explicit verification-folder argument. Real games and the Editor keep real UTC time and random identities. Isolated captures share fixture paths, fixed time/identity generation and new-market seeds, wait for pending estimates and sample animations at fixed phases. Named race photos use the shared simulation at exact ticks, with the original test race restored afterward. Manual sound-bench photos reset live history and sample 360 fixed ticks. Ordinary bench recording is unchanged. `capture-inputs.jsonl` records image occurrences, dimensions and UI labels for investigation; it is diagnostic metadata, not a complete physics snapshot.

Repeated image names receive occurrence suffixes. Capture mode skips the host-clamped oversized desktop-window probe while retaining the true 3840×2160 render-target checks. Prior attempts are archived rather than overwritten. A missing protocol trace fails the capture script. The deterministic contract has no dynamic exemptions and retains the original pixel/tile budgets. See [the deterministic investigation](../reports/render-pipeline-deterministic-20261016/CHANGES.md) for coverage, measured differences and limits. Numerical success remains separate from user approval of the interface design.
