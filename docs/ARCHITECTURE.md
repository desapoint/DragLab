# Unity layout and development ownership

Current persistence is SQLite, documented in [SAVE_STORAGE_DIRECTION.md](SAVE_STORAGE_DIRECTION.md). The approved [architecture/performance plan](ARCHITECTURE_PERFORMANCE_PLAN.md) records the proposed incremental evolution and checkpoint gates; its proposed command/index/schema boundaries are not yet implemented. Historical descriptions below must not be read as replacing the current storage contract.

## Boundaries

Implementation sequence is defined in [IMPLEMENTATION_PHASES.md](IMPLEMENTATION_PHASES.md). Define contracts/needed runtime boundaries in 2A, parts/OEM resolution in 2B, and unique vehicle/engine/part ownership plus recoverable migration in 2C. Inventory replacement and the physical bench precede contact/fuel/wear work. Repeated purchase, assembly valuation and salvage use these foundations in 3A–3D; they must not trigger a second identity/save rewrite. These are planned boundaries, not implemented types.

`Domain` has no Unity dependency. Use SI units: m, m/s, kg, Nm and seconds. Convert to km/h only in presentation. `VehicleSpec` defines stock engineering data; `Tune` adds gameplay modifications; `DriverSettings` defines assists. `CarState` is runtime-only. The same `CarSimulation` powers player, opponent, dyno benchmark and telemetry. Unity physics components must not simultaneously drive the same car position.

`RaceSimulation` owns countdown, red lights, launch timing, finish interpolation, split recording and winner comparison. Use a fixed 1/120-second tick independent of frame rate. The runtime buffers button edges and consumes them once per tick. It caps catch-up at 0.1 seconds per rendered frame to avoid a long stall advancing the entire race. Focus loss pauses play, clearing buffered and held controls. Results compare reaction + elapsed time, not elapsed time alone. `RaceTelemetry` samples simulation state at approximately 10 Hz with a 1,000-sample ceiling.

A launch command occurs at the end of its simulation tick; driving integration starts on the following interval. This avoids charging distance to a car before its recorded launch time. Benchmarks interpolate the finish crossing too, so an identical assisted build agrees with race ET. This corrects the previous one-tick timing offset; older best records are retained and may differ by about 0.008 s from the corrected timing.

`PlayerProfile` owns cash, reputation, owned builds and business claims. Only the runtime result path awards a completed race, once. Reputation is awarded for first career wins. Workbench simulations never award money. File writes use a same-directory temp file then replacement, preserving the prior save as a backup. Local timestamps are a single-player convenience, not an anti-cheat system; rollback produces no negative payout. Business rate changes settle old earnings first.

`OwnedCar` owns records, adjustment presets, vehicle/chassis/engine IDs and installed slot references. Profile schema 3 keeps one authoritative part ledger with exclusive location/parent/slot and condition. Migration converts legacy ranks through recipes, retains the original `.legacy-v1` backup and saves identities before publishing. The one-time driveline version 2 migration adds applicable front/rear branch parts without healing retained components; later removals stay removed. Failed/newer-schema recovery cannot overwrite the original. `MechanicsTransactions` clones, checks revision, applies/validates a candidate, atomically persists and publishes it. Engine-critical failures and incomplete engine builds block race entry; brake/drive failures remain owned and produce component-specific consequences and warnings. See [AWD/failure details](COMPONENT_FAILURES_AWD.md).

`MechanicalCatalog` authors fictional compatible definitions/OEM recipes. `MechanicsOwnership.Resolve` derives a copied specification/tune from fitted parts and retained adjustments. Resolved multipliers cannot stack legacy rank bonuses. Rank fields remain a compatibility projection for old records/authoring fixtures. Hardware presets do not restore purchases. Prices are provisional; driving-based wear and independent contact remain later gates. `RaceSessionFactory` copies specs, tune and driver settings for both cars before each race.

`PhysicalDrivingSession` uses the same `CarSimulation` engine/coupling/road methods without `RaceSimulation`. Independent neutral retains flywheel RPM and uses the shared unpowered-road/brake solve. Every input and chronological sample is retained at 120 Hz. `RunSnapshot` captures version/model, seed, copied spec/tune/driver, component bindings/conditions and starting fuel. `PhysicalBenchTransfer` copies Garage data; the separate scene never loads/saves progression. Fixed-RPM/load/roller overrides remain in the acoustic bench. Full-road wheel state is still demand-based until 2G–2H.

`OwnedCar.lastPass` stores the last valid finish's distance, ET, reaction, splits, trap and copied Tune/DriverSettings. These are serialized DTOs, treated as read-only snapshots by callers. Capture rejects incomplete/disqualified runs; comparison rejects different distances. The runtime keeps the previous record before settlement and displays the new record's delta. Older saves have a null last pass rather than invented history. Practice uses the selected vehicle's stock opponent, records a legitimate finish and saves exactly once without awarding cash or reputation. Workbench experiments never touch these records.

`DragStripView` owns scenery, starting-tree bulbs and finish position. All track layers scroll from authoritative simulation distance; view-space distance is compressed by 0.18 and is a presentation choice. Car assembly detaches/deactivates old parts immediately before deferred runtime destruction, preventing an overlapping frame when switching vehicles.

`VehicleDefinition` and `CareerEventDefinition` are authoring assets. Edit their Inspector values, then run validation/benchmarks. The preparation tool preserves existing assets. Model IDs are catalog keys; owned instance IDs identify slot/condition ownership. Art IDs are presentation references and may change independently. Runtime assembly reads sprite manifests; no axle location is hardcoded in the view. Normalized centered pivots and 200 pixels/unit are the current import contract.

`CarSimulation.Shutdown` continues distance and wheel rotation after a finish while preserving recorded timing. Each car starts shutdown immediately at its own crossing, including while the other car is still racing. When both cars are done, `RaceSimulation.Shutdown` advances only shutdown motion; race time remains fixed. Player auto-braking can be disabled in saved driving settings. Full brake force is capped by both the authored deceleration (zero = modeled 8 m/s²) and tire grip. This is a straight-line deceleration model without ABS, lockup, brake heat, axle bias or engine braking. Result settlement remains once per race, and race telemetry stops at the player's finish. Pause also freezes shutdown.

`CarState.gear == 0` represents staging neutral; forward gears remain 1-based. New cars initialize in neutral with `stagingBrakesHeld` and full brake pressure. `Stage` keeps speed, wheel torque and slip at zero while engine RPM responds independently of clutch pressure. `Launch` engages first and clears the automatic staging brake hold without resetting engine RPM or held gas. Manual brake input is applied normally on the next driving tick. Staging persists until a valid launch, including waiting after green; disqualified cars remain neutral and braked. Gear commands are rejected before launch, and neutral never indexes a forward gear ratio.

## Current model limits

The owned-ID and exclusive-parent foundation is implemented in 2C. Player-facing repeated purchases, detached/retained engine trees, paid salvage and separate assembly/chassis/car valuation remain 3A–3D. Current purchase UI still permits one copy per model; same-model fixture instances already remain independent. Later quotes use actual captured contents/condition and authored market factors, without forcing assembly totals to equal loose-part sums. See [repeat ownership, salvage and assembly valuation](GAME_PLAN.md#required-repeat-ownership-partial-salvage-and-assembly-valuation).

Slice 2 ownership boundary: immutable `PartDefinition` and engine/OEM build recipes describe fitment, quality, limits and defaults; unique `PartInstance` records own persistent condition/history. Player inventory and installed slot references share a single ownership ledger. A build resolver validates the complete assembly and derives safe defaults, output and mass/inertia; it replaces generic mechanical rank multipliers. Atomic buy/swap/remove/reuse/sell operations and run wear/fuel checkpoints must not duplicate instances or condition changes. Bench snapshots remain isolated copies. Ownership, compatible fitted-part resolution, inventory and atomic transactions now exist; actual component stress/failure is shared by race and bench. Race condition commits persist and replacements retain old instances. The complete fuel/contact/cooling/category-specific wear matrix and interrupted-run checkpoints remain later gates. See [the Slice 2 parts/wear specification](GAME_PLAN.md#required-modular-components-compatibility-and-inventory). Slice 3 balances the existing functional parts transactions and service/resale economics.

Contact slip is demand-based and uses simplified longitudinal load transfer. `WheelProfile` captures assembly mass/diameter/width and computes four-wheel rotational inertia, static mass changes and equivalent acceleration/braking load. Manual clutch synchronization uses reflected rolling inertia; independent axle-spin/contact integration remains future work. `TransmissionSpec` separates Manual/DCT/converter Automatic/CVT hardware from driver input presets. DCT retains torque through faster handover, automatic has converter multiplication/slip/lockup, and CVT changes bounded ratios continuously without discrete shift edges. Manual rev-match mismatch reduces transmitted torque temporarily; unsafe downshifts are blocked.

`ClutchDynamics` converts engine-side torque imbalance into RPM change through crank/core plus calculated flywheel inertia. `FlywheelSpec` defines annular-disc mass/radii; tune mass changes physical inertia. `FlywheelDynamics` publishes stored energy/angular momentum. Bounded clutch capacity and reflected rolling inertia synchronize the engine with driven wheels; changing gear preserves RPM instead of assigning a new speed. Manual handover disconnects shaft torque without forcing combustion off, and rev-match assistance applies bounded torque. Converter fluid load observes turbine/pump speed difference; lock-up uses finite synchronization and speed hysteresis, releasing during shifts. Zero core-inertia/capacity fields resolve to 0.12 kg m² plus the modeled flywheel, and 1.35 times peak stock torque. Gearbox stages raise capacity 15% per stage. Manual engagement can pull RPM below idle and stall; clutch-in + Enter restarts. Converter/CVT hardware ignores the manual pedal. Clutch heat, detailed engine braking and physical staging-beam rollout remain future work. Reaction is measured from the launch command, so subsequent clutch-release delay is included in ET. See `FLYWHEEL.md` for the fixed-load bench approximation and legacy-field interpretation.

`EngineBehaviorProfile` captures factory/upgraded main and launch limiter styles/setpoints/cut methods. Hard limiting retains hysteresis; soft limiting progressively reduces combustion; None permits overrev damage/failure. `EngineBehaviorDynamics` advances warmup, fueling hesitation, idle irregularity, discrete pops, duration-limited launch/overrun anti-lag and exhaust heat/wear before induction and transmission. Exhaust energy can sustain compressors through cuts without adding crank torque. Output uses the same combustion fraction everywhere. Stalls/failure stop combustion audio. Transient engine-control state is per pass, while the shared `MechanicalStress` owns copied installed-part conditions that races commit to the player profile. Failed parts require replacement; bench repair affects isolated copies only. Simulation presets/parameter assists are captured by the same `DriverSettings`; there is no alternate bench physics. See `POWERTRAIN.md`.

`RaceInputAdapter` reads device state once per render frame and buffers action edges for a single fixed-tick consumption. W and Space are interchangeable held throttle keys. `RaceSimulation` interprets E / shift-up as first-gear engagement from staged neutral (CVT Drive), an ordinary upshift while driving, or restart while stalled with the existing clutch requirement. Enter retains its explicit launch/restart edge. Assisted/manual early engagement red-lights; automatic launch ignores engagement edges and keeps its scheduled reaction. A newly launched car starts driving on the next tick, so the launch edge cannot also shift into second. Consuming action edges never consumes pedal holds. The six touch controls are gas, clutch, down, combined up/launch/restart, pause and brake. Every touch ID captures one control and can set analog pressure without affecting another finger; touch-generated mouse emulation is ignored while touch contacts exist. Pause/focus transitions clear contacts and require pointers to be released before rearming, preventing an entering/resuming UI click from becoming a pedal press. Keyboard pedal holds are read immediately on the next active frame. The hit zones are shared with the temporary debug overlay; controller input and production uGUI/UI Toolkit are separate future adapters.

Before launch, an explicit gas pedal overrides the assisted tuned-RPM hold and free-revs the engine in any launch mode. That override lasts until launch, allowing release to reduce RPM instead of snapping back to the tune. Without two-step or a pedal override, assisted staging and benchmarks retain the tuned RPM. Enabled two-step uses actual combustion cuts/reduction at launch RPM while retaining neutral/brake hold. Launch releases the lower limit without resetting pressure. Manual shifts disconnect shaft torque while gas remains held; other transmission hardware applies its own handover.

`EngineAudio` owns a silent clock clip and a non-spatial AudioSource; `OnAudioFilterRead` fills its buffers from `EngineSoundSynth`. Only immutable `EngineSoundFrame` references cross from the main thread to DSP. A captured session holds its own hardware profile and generator, so changing cars cannot combine one car's frame with another car's hardware. The callback uses no Unity APIs, file operations, locks or sample/block allocations. Output sample-rate changes are published from the main thread. The generated mono signal is duplicated to output channels, DC-filtered and softly saturated. Phase remains continuous across blocks. Mute/pause clears output and release tails.

`VehicleSpec.induction` owns mechanical compressor topology, factory valve, pressure/flow limits, spool/coast, charge response, efficiency and drive losses. `InductionProfile` copies compressor specs and tune at car construction; `InductionDynamics` advances once per fixed tick in staging/driving/shutdown, before torque is passed to the clutch. `DragMath.Torque` exposes settled WOT torque for dyno/shift optimization; actual engine torque/HP uses current compressor states. Factory boosted torque tables are normalized to an underlying engine curve before reapplying hardware, preventing double-counting. Benchmarks and both race cars receive matching neutral staging histories. Shift targets are cached per captured build, avoiding repeated curve scans in physics ticks. See `INDUCTION.md` for parameters and limits.

`VehicleSpec.sound` owns cylinder/layout, exhaust tone, charger whine ratio and layer gains. Physical displacement owns engine size; zero falls back to the sound-profile size. Older acoustic induction/boost/spool/valve fields remain for initial migration only. Preparation uses `sound.version = 1` and `induction.version = 2`, preserving later authoring edits and torque tables. Tune owns exhaust stages, induction kit, turbo size and boost/pulley/valve adjustments. Presets restore the latter adjustments while retaining purchased/chosen hardware. Exhaust stages change tone rather than power. Prior serialized kit IDs are unchanged and absent tune settings use nominal values.

`EngineSoundController` observes physical pressure, rotor speed, blower drive torque, combustion/fueling state and monotonic release/pop events. It never advances physics. Pause/mute clears tails; resume rebases events without changing pressure, heat or warmup. Combustion/turbo have no continuous white-noise layer; valve air and a quieter tire layer are filtered. Lower exhaust/crank/bank pulses and darker filtering retain engine-specific depth through high-RPM pulls; fueling/cam/cold state controls rawness, gulp/bog/burble and mechanical clatter. Twin/mixed kits have separate quieter compressor voices. `EngineSoundAudition` advances scripted induction/fueling at 120 Hz through the same controller/generator for eight-second WAVs. See `ENGINE_AUDIO.md`.

## Development tool workflow

`EngineTestScene` owns an isolated `EngineBenchConfig` and endless `EngineTestBench`, without RaceSimulation or ProfileStore. The fixture shares fueling, limiter, induction, torque and sample generation, with explicit dyno-load/roller inputs and a static RPM override. `EngineBenchScenarios` defines inputs by integer 120 Hz ticks. Repeat/A/B capture deep configs and rebuild physical/audio state. `EngineBenchRenderer` uses the same fixture at fixed 60 Hz publication/44.1 kHz PCM for sample-exact exports. Live hardware changes capture fresh profiles; invalid drafts cannot replace the current valid bench. See `ENGINE_TEST_BENCH.md`.

`EngineBenchInput` keeps persistent Slider/Keyboard/Scenario ownership separate from applied feedback. Keyboard takeover clears latched pedals and static RPM, then releases read zero until explicit **Use sliders** or reset. Keyboard-owned fields are disabled/read-only. W/Space claims control even from numeric focus; pending hardware debounces are settled first. Reflection edits a copy of feedback, and commits only actual enabled input events with widget changes: layout/repaint never write into configuration. GUI structure stays constant across scenario/manual feedback. The bench's protected powered-on state has an idle floor; manual shifts disconnect the shaft while combustion remains active. Fault testing remains opt-in. Race and bench share the calculated engine/flywheel inertia; the bench retains its independent assigned-load fixture.

`EngineBenchDyno` captures every fixed tick, with an initial sample and complete endpoint. Historical runs own copied configurations and independent chronological sample collections. Reset/config changes and scenario completion archive traces; pause contributes no samples. History holds six whole runs and ten-minute segments bound long captures. `EngineBenchDynoView` renders time/RPM paths with separate HP/Nm scales in a batched GL pass, preserving descending RPM and cuts. CSV retains all samples and flags shaft interruption separately from engine output. These tools have no profile/economy dependencies and do not change race telemetry's finish-limited policy.

`EngineSoundSpec.exhaustSystem` contains an ordered, deeply copied component chain. `ExhaustFilter` captures its numeric amount/dB/cutoff/softening/EQ/Q values and allocates filter state only at configuration. It processes combustion/overrun/pops before adding independent intake, clatter, compressor, valve and tire layers. DSP coefficients update only for sample-rate changes; mute clears filter memory. Missing/empty chains retain the prior path. `exhaustSystem.version = 1` preserves subsequent factory authoring. Exhaust changes are acoustic here, with no additional HP/backpressure model.

1. Use **DragLab → Prepare First Slice** once, then preserve and edit the generated definitions.
2. Open **Vehicle Workbench**, select a vehicle and inspect its torque/HP curve.
3. Change the definition in its Inspector for stock data; change sliders for temporary test tune.
4. Run a benchmark before and after changes, then export CSV to compare distance/RPM/slip. **Compare current build** runs thirteen trials: baseline, five launch RPMs and seven final drives. Each trial copies/clamps its tune and uses the same selected traction assist. Comparison CSV exports the captured settings and deltas, even if the sliders subsequently change.
5. Import/export JSON for reproducible experiments. Imports reject invalid data, unknown art and changes to stable vehicle IDs.
6. Run **Verify Foundation** after physics/data changes. It writes `reports/unity-verification.txt` only after checks pass.

## Shared service and fluid simulation

`ServiceHardware` appends compatible engine/service definitions and applies physical cam/flow/capacity metadata. `ServiceDynamics` projects deterministic component condition, valve control and lubrication; `FluidDynamics` advances quantity, temperature, pressure, loss and aging inside the same `CarSimulation` ticks used by races and the physical bench. `ServiceOperations` applies fault-specific service through existing ownership transactions. `FluidState` is owned by the car, copied to races/bench/inspection and deep-copied/exact-encoded in continuation checkpoints. Installed capacity changes never refill the saved quantity. One-time service-hardware migration is separate from recurring profile load and preserves all previous identities. Optional engine-off cooldown is explicitly simulated; no external time is read by the solver. See [scope and tooling](WEAR_FLUIDS_AND_SERVICE.md).
